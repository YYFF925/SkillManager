# Feature Specification: 本机 Host、统一管理站与内置管理 Agent

**Feature Branch**: `003-host-station-agent`

**Created**: 2026-11-11

**Status**: Draft — 依据 [ADR 0002](../../docs/adr/0002-host-management-station-and-agent.md)、[项目原则](../../.specify/memory/constitution.md)（v2.1.0）与 2026-11-11 产品讨论整理。

**Input**: 用户指令 `/speckit-specify`。功能描述即同一讨论已裁决的方向：每台电脑上的本机管理服务（Host）、一次登录后切换设备的统一管理站、以及跑在当前 Host 上的内置管理 Agent。技能内容与本机状态的边界仍以 [ADR 0001](../../docs/adr/0001-library-and-local-state.md) 与 [002 规格](../002-skill-management/spec.md) 为准；本规格只定义新入口与新能力，不重写技能管理细则。

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准。本规格取代 002 User Story 8 场景 6 及需求记录中「不提供管理其他机器上 Agent」的表述：不进入没有 Host 的机器；已安装 Host 的设备经管理站管理该设备上 Skill Manager 的全部能力。界面语言仅提供简体中文。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在无窗口的机器上接入 Host (Priority: P1)

用户在云电脑或其它不便使用图形窗口的机器上，把 Skill Manager 作为本机服务跑起来：用 git clone 得到已有的 SkillManagerVault，用一键命令接入并启动 Host。该机通常已有编码 Agent，用户把安装 Skill 交给它，由它按说明完成 clone、配置 Host、对接管理站。Host 随系统开机启动、关机即停；关掉以后可以用启动命令由用户或 Agent 再拉起来。

**Why this priority**: 没有本机 Host，远程和管理 Agent 都无处落地；这是另外两条故事的前提，也直接对应「云电脑桌面不好远程」的实际困境。

**Independent Test**: 在一台不打开 Skill Manager 图形窗口的机器上，仅用一键命令或安装 Skill 完成 clone 与 Host 启动，用命令确认服务在跑、库路径正确；不依赖管理站网页或内置管理 Agent 对话。

**Acceptance Scenarios**:

1. **Given** 用户已有 SkillManagerVault 远端，目标机器上还没有本地克隆，**When** 执行软件提供的一键接入命令（或安装 Skill 按同样步骤执行），**Then** 该机得到该库的本地克隆，Host 指向它并开始提供本机管理能力；不出现图形克隆向导，也不在应用里「新建一座库」。
2. **Given** Host 已按本机服务安装，**When** 机器开机，**Then** Host 自行启动；机器关机后 Host 停止。第一版不唤醒已休眠的电脑。
3. **Given** Host 被用户或系统关掉，**When** 用户或该机上的 Agent 执行软件提供的启动命令，**Then** Host 重新提供本机管理能力。
4. **Given** 该机已有编码 Agent，**When** 用户启用安装 Skill，**Then** 该 Agent 能按技能说明完成 clone、配置并启动 Host、对接管理站；安装 Skill 与配套维护 Skill 不是同一份。
5. **Given** 同一台机器上桌面与无窗口服务都可能启动，**When** 任一方已占用本机状态目录，**Then** 另一方不得再起一套互相打架的 Host；本机桌面只管理本机，不切换其它设备。
6. **Given** 管理站当时不可用，**When** 用户在本机使用桌面或命令行，**Then** 仍能管理这台机器上的库与部署。

---

### User Story 2 - 登录管理站并切换设备管理当前那一台 (Priority: P1)

用户用一个 HTTPS 地址打开统一管理站，用唯一管理员账号（密码 + 基于时间的一次性密码）登录，保持登录时长可配置。各机 Host 用对接码主动连出，不必对每台开放公网端口或登录页。登录后切换设备，进入**当前那一台**的完整 Skill Manager 管理界面（技能库、部署、上游、预设、Hermes、工具、设置中的管理能力），一次只管这一台，不做所有设备的总览或批量指挥。管理站不保存用户的 Vault。

**Why this priority**: 「在外面管家里的 Hermes 技能、管云电脑上的库」是本功能的直接用户价值；没有这一条，Host 只是本机守护进程。

**Independent Test**: 准备管理站与至少两台已对接 Host（可为实验用的两份本机状态）。浏览器只登录一次，切换设备后分别改各机的一条管理资料（例如中文注释），验证改动落在对应机器、另一台不受影响；不依赖内置管理 Agent。

**Acceptance Scenarios**:

1. **Given** 管理站尚未有管理员，**When** 首次启动，**Then** 创建那一个管理员并绑定一次性密码（提供二维码、密钥和一次性恢复码）；之后只有这一名操作者。
2. **Given** 用户用正确密码与一次性密码登录，**When** 登录成功，**Then** 在所配置的保持时长内再次打开无需重新输入；时长可配置。
3. **Given** 用户丢失手机且仍有恢复码，**When** 使用恢复码，**Then** 能重新进入并重新绑定一次性密码。恢复码也丢失时，只能在管理站所在那台机器上用本地命令重置，不能经公网自助开新账号。
4. **Given** 用户在管理站生成一次性对接码，**When** 某机 Host 填入管理站地址与该码并连出，**Then** 该设备出现在可切换列表中；该机不必对公网开放端口或单独登录页。
5. **Given** 设备已对接，**When** 用户改名或解除对接，**Then** 列表立即反映；解除后该机 Host 不能再经管理站操作，需重新对接。
6. **Given** 某设备当前离线（关机、未启动 Host 或网络中断），**When** 用户在列表中查看，**Then** 能看出离线且不能对它执行管理操作；在线设备不受牵连。
7. **Given** 用户切换到设备甲，**When** 浏览与修改技能库、部署、上游、预设、Hermes 档案启用、工具资料或本机 Agent 目录等 002 已有管理能力，**Then** 对象与结果都在甲这台机器上；切到乙则只管乙。不出现「一块屏幕同时编排所有设备」的界面。
8. **Given** 用户在远程界面填写 Vault 路径或 Agent 技能目录，**When** 选择或输入路径，**Then** 该路径属于当前 Host 所在机器，而不是用户正在用的浏览器那台电脑。远程界面不提供托盘、关窗收起、桌面应用更新。
9. **Given** 两个浏览器同时打开同一台设备，**When** 各自做非破坏性修改，**Then** 均被允许；破坏性确认只对发出该次确认的那次会话有效。
10. **Given** 管理站不持有 Vault，**When** 用户经管理站查看技能内容，**Then** 内容来自当前设备上的本地克隆，管理站不另存一份技能库。

### User Story 3 - 在当前设备上用对话完成与界面同类的管理 (Priority: P1)

用户在本机桌面或经管理站打开的网页里，与内置管理 Agent 多轮对话，完成与当前图形界面同类的库管理：查看与搜索、注释与分类标签、入库与上游、部署与预设、Hermes 档案、工具检查、库同步等。打开某技能、某分类或勾选若干对象时，对话自动带上当前范围，用户可以说「这个技能」「这些技能」。任务在发出时钉死对象；切页只影响之后的新指令。Agent 只执行用户在对话里发起的任务，不在无人指令时主动改库。删除技能与覆盖必须经当前界面确认；push 不逐步确认。

**Why this priority**: 在软件内部用对话管理，而不是把步骤复制到外部编码 Agent，是并列的产品方向；必须跑在被管理那台机器上，远程时也是管当前设备。

**Independent Test**: 在本机桌面（不经过管理站）打开对话：进入一个技能详情，说「完善中文注释」，验证注释写入该技能且无需用户填写命令；再切到另一技能发新指令，验证新指令作用于新对象、前一任务若未完成仍作用于原对象。

**Acceptance Scenarios**:

1. **Given** 当前设备已能运行 Host，**When** 用户在桌面或远程网页打开内置管理 Agent，**Then** 对话在这台 Host 上执行，浏览器或另一台电脑不运行该管理模型。
2. **Given** 用户打开某技能详情，**When** 说「完善中文注释」，**Then** Agent 针对该技能写入或更新中文注释，用户不必知道命令或参数。
3. **Given** 用户在某分类下，**When** 说「检查这些技能的更新」，**Then** 检查范围是当前分类中的技能，而不是全库或其它页的对象。
4. **Given** 用户勾选若干技能，**When** 说「把选中的这些部署到某某目标」，**Then** 仅这些技能被部署；局部失败时分别说明成功与未完成项。
5. **Given** Agent 正在处理技能 A，**When** 用户切到技能 B 再发「完善这个技能的注释」，**Then** 进行中的任务仍针对 A，新指令针对 B。
6. **Given** 用户要求删除某技能或覆盖已有部署副本，**When** Agent 准备执行，**Then** 当前界面必须先展示对象与后果并得到该次会话的确认，不得仅凭对话里的「已同意」执行；改注释、分类、标签、普通部署与远端 push 不逐步确认。
7. **Given** 远程网页或内置管理 Agent 保存了库内修改且 GUI 自动上传授权已存在，**When** 上传自己的 SkillManagerVault，**Then** 不逐步弹出确认。外部编码 Agent 经配套维护 Skill 改库时，仍按 002：每次询问后才上传。
8. **Given** 用户没有在对话里下任务，**When** Host 空闲，**Then** 内置管理 Agent 不巡检、不自动采用上游、不自动入库、不自动安装工具、不无人值守 push。既有定时上游检查、库拉取与工具版本检查仍按 002 由 Host 后台执行。
9. **Given** 管理 Agent 所用命令行工具本机没有，**When** 用户首次要使用对话，**Then** 软件检测已装项，没有则在软件内安装或启用，不把第三方工具打进 Skill Manager 安装包。该工具的模型登录仍由它自己完成；Skill Manager 不把密钥存进管理站。选型锁定后，安装 Skill 须能指导该机上的编码 Agent 完成这次登录。
10. **Given** 用户结束或再次打开对话，**When** 查看历史，**Then** 对话留在该机 Host 的本机状态中，不进入 SkillManagerVault，也不随库同步到其它电脑。

---

### Edge Cases

- 对接码过期、已使用或填错：设备不能加入列表，原因可理解，已对接设备不受影响。
- Host 在操作中途掉线：进行中的动作失败并说清；切回该设备前不得把失败显示成成功。
- 目标机器上 git clone 失败（认证、磁盘、路径占用）：接入中止，已有库不被覆盖。
- 内置管理 Agent 所用命令行尚未登录模型：对话必须说明无法执行的原因，不得把「任务已生成」写成已经改库。
- 会话过期后提交破坏性确认：必须拒绝，需重新登录后再确认。
- 拉取库时发生冲突：沿用 002 现有提示（交给外部处理），本规格不新增合并界面。
- 管理站证书或公网地址不可用：本机桌面与命令行不受影响。
- 用户同时打开桌面窗口与远程网页管同一台：允许；同一本机状态目录仍只有一个 Host。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每台安装了 Skill Manager 的电脑必须有且仅有一个 Host，作为该机图形界面、远程界面、命令行与内置管理 Agent 的统一操作入口。技能管理的业务结果必须与 002 相同，不得因入口不同出现第二套规则或第二份技能库。
- **FR-002**: 本机桌面必须只管理本机 Host，不得经桌面切换其它设备。没有管理站时，本机桌面与命令行必须仍可独立使用。
- **FR-003**: 无窗口 Host 必须以本机服务运行：随系统开机启动，关机即停。软件必须提供可复制的启动命令，使用户或该机上的 Agent 能把已关闭的 Host 拉起。第一版不得要求唤醒已休眠电脑。
- **FR-004**: 新机器接入 SkillManagerVault 必须通过 git clone 已有远端，不得提供图形克隆向导，不得在应用内创建另一座中央库。软件必须提供一键命令，完成克隆并让本机 Host 指向该克隆。
- **FR-005**: 必须提供与配套维护 Skill 分开的安装 Skill，供新机器上已有的编码 Agent 使用，指导 clone、配置并启动 Host、对接管理站；内置管理 Agent 所用命令行工具选型锁定后，该技能必须能指导该工具的登录。
- **FR-006**: 命令行在 Host 未运行时可直接完成本机管理；Host 已运行时必须经 Host 执行，避免与图形界面或 Agent 同时改同一份库而无协调。
- **FR-007**: 管理站必须提供用户指定的 HTTPS 入口与唯一管理员登录。登录方式为账号密码加基于时间的一次性密码；绑定过程必须提供二维码、密钥与一次性恢复码；登录后保持时长必须可配置。
- **FR-008**: 管理站首次启动必须创建那一个管理员。丢失恢复码后，只允许在管理站所在机器上用本地命令重置，不得提供公网自助注册或多人账号。
- **FR-009**: 各机 Host 必须用管理站地址与一次性对接码主动连出；不得要求每台设备对公网开放端口或提供独立登录页。设备必须能改名与解除对接。
- **FR-010**: 设备列表必须区分在线与离线。离线设备可见但不可操作。登录后切换设备必须进入当前那一台的完整管理界面，不得做成所有设备的总览或批量指挥。
- **FR-011**: 管理站不得持有用户的 SkillManagerVault，不得代替各机的部署目录、Hermes 目录或内置管理 Agent 的运行。
- **FR-012**: 经管理站打开的界面必须覆盖 002 已有的技能管理能力（库维护、获取与上游、部署、预设、Hermes 档案、工具中心、本机 Agent 与指令、同步）。远程界面不得提供托盘、关窗收起、桌面应用更新。路径类配置必须指向当前 Host 所在机器。
- **FR-013**: 同一 Host 必须允许多个界面会话同时打开。破坏性操作的确认必须绑定发出确认的那次会话。
- **FR-014**: 内置管理 Agent 必须作为产品内的对话能力提供，跑在当前被管理那台机器的 Host 上。它不是设置页里的「内置 Agent 名单」（部署目标），也不是把任务复制到软件外的编码 Agent。
- **FR-015**: 内置管理 Agent 必须能完成与当前图形界面同类的管理动作（002 已有业务，含组合多步）。用户不必了解命令或参数。当前页面、管理域、选中对象必须自动成为对话上下文；任务在发出时钉死对象，之后切页只影响新指令。
- **FR-016**: 内置管理 Agent 只响应对话中用户发起的任务。不得在无人指令时主动巡检、采用上游、入库、安装升级或 push。002 已规定的定时上游检查、库拉取与工具版本检查仍由 Host 后台执行，与对话无关。
- **FR-017**: 软件必须检测本机是否已有内置管理 Agent 所用的命令行工具；没有则在软件内安装或启用，不得把第三方工具打进 Skill Manager 安装包。该工具的认证与模型密钥不得存入管理站。具体默认安装哪一家不在本规格锁定。
- **FR-018**: 对话历史必须保存在该机 Host 的本机状态中，不得写入 SkillManagerVault，不得随库同步到其它电脑。
- **FR-019**: 删除技能（含因此清理受管部署）与覆盖（覆盖部署副本、丢弃副本独有改动）必须先由当前客户端确认带对象预览的操作计划，再执行。不得采信 Agent 口头「用户已同意」。改注释、分类、标签、普通部署以及远端 push 不得逐步确认。
- **FR-020**: 本机或远程图形界面保存后的上传，沿用 002 已有的 GUI 一次性自动上传授权，不改为每个 push 弹窗。内置管理 Agent 的 push 同样不逐步确认。外部编码 Agent 改库后的上传仍按 002：每次询问后才执行。
- **FR-021**: 库拉取冲突的专门处理不纳入本规格，沿用 002 现有提示与继续方式。主动维护、跨设备总览、多人账号、唤醒休眠电脑、管理站自行申请证书，均不纳入。
- **FR-022**: 信息展示必须区分已知事实、待确认状态和执行结果；未检查、检查失败、命令行未登录或任务已生成，均不得表达为已经改库成功。

### Key Entities

- **Host（本机管理服务）**: 一台电脑上唯一的本机管理入口。持有该机 Vault 克隆路径、本机状态、与管理站的对接、内置管理 Agent 的运行。
- **管理站**: 公网（或用户指定）HTTPS 入口。持有唯一管理员、登录会话、设备对接关系。不持有 Vault。
- **设备**: 已对接的一台 Host。有名称、在线状态、可解除。表示「当前在管哪一台」，不是另一座技能库。
- **管理员会话**: 单一操作者的登录；保持时长可配置；破坏性确认绑在具体会话上。
- **内置管理 Agent 任务**: 一次对话指令及其钉死的对象快照、进度与结果。历史留在该机本机状态。
- **操作计划**: 删除或覆盖前必须确认的对象与后果说明，由当前会话确认后才执行。
- **安装 Skill**: 指导新机器上已有编码 Agent 接入 Host 与 Vault 的技能；与配套维护 Skill 分开。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 操作者从另一地点用浏览器登录管理站后，能在 3 分钟内切换到一台已在线设备，并完成一次非破坏性修改（例如改中文注释）；该修改只出现在该设备的库中。
- **SC-002**: 一台没有图形窗口的机器，仅用一键命令或安装 Skill 完成 clone 与 Host 启动后，能在管理站设备列表中被选中并管理，无需再为该机开放公网端口。
- **SC-003**: 在技能详情发出「完善中文注释」且本机管理 Agent 可用时，操作者不必填写命令，该技能的中文注释被写入。
- **SC-004**: 删除技能在未确认时不会发生；连续多次上传自己的库不会出现逐步确认弹窗。
- **SC-005**: 管理站不可用时，本机图形界面仍能完成一次本机库内非破坏性修改。
- **SC-006**: 进行中的内置管理 Agent 任务在用户切到其它页面后，仍作用于发出时的对象；新指令作用于新页面对象。
- **SC-007**: 经远程界面或内置管理 Agent 维护的技能内容，仍只存在于用户自己的 SkillManagerVault 各机克隆中，不因远程管理多出第二份库内容。

## Assumptions

- 操作者是同一人；多台电脑与远程入口是多设备，不是多用户。
- 用户已有 SkillManagerVault 远端；新机器是 clone，不是从零建库。
- 用户为管理站准备 HTTPS 地址（例如已有反代）；第一版不要求管理站自己申请证书。
- 云电脑等目标机器上通常已有编码 Agent，能阅读并执行安装 Skill。
- 技能管理的字段、上游、部署、预设、Hermes、工具中心等行为以 002 为准，除非本规格明文取代。
- 002 User Story 8 场景 6（不远程管理其它机器上的 Agent）由本规格取代；002 FR-038 对**外部编码 Agent** 的每次询问仍有效。
- 内置管理 Agent 默认使用哪一家命令行工具，在实现规划阶段锁定，不阻塞本规格。
- 库拉取冲突的专门产品、主动维护、跨设备总览，明确留到后续专题。
- 登录页、设备切换、对话界面的具体布局在设计层给出，本规格只约束行为与范围。
- 界面仅简体中文，与 002 一致。
