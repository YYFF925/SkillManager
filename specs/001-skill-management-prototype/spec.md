# Feature Specification: 技能管理主流程交互原型

**Feature Branch**: 未创建；本次未配置分支创建 Hook（扩展钩子）。

**Created**: 2026-10-14

**Status**: Draft — 在本项目直接迭代可操作原型；正式产品规格已由 [002](../002-skill-management/spec.md) 承担，本规格只定义原型应表达的业务行为与边界。

**Input**: 根据已确认的 Skill Manager 需求与项目原则，形成用于本项目直接制作和迭代的可操作交互原型规格，验证上游技能入库、管理层维护、部署、上游更新、自己的库跨电脑同步及已有技能收编的完整流程。

本规格定义的是原型应表达和允许用户体验的业务行为。正式产品的核心要求作为原型约束；模拟资料、展示布局和体验方案是可调整的设计假设。原型完成不代表真实仓库同步、文件部署或 CLI（命令行）能力已经实现。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从上游选择技能进入自己的库 (Priority: P1)

用户发现一个来源仓库，查看其中的技能，选择需要的技能放入编码或龙虾技能库。入库后用户知道技能来自哪里、保存在哪里，以及它尚未部署给哪些 Agent（代理）。

**Why this priority**: 这是上游技能进入个人资产库的起点，必须让用户理解来源仓库与 SkillVault 的关系。

**Independent Test**: 从“来源尚未登记”的预置情境开始，完成一次部分入库，在库中找到选择的技能及来源资料，无需先完成其他场景。

**Acceptance Scenarios**:

1. **Given** 来源仓库包含三个技能，**When** 用户只选择两个技能入库，**Then** 只有选中的两个进入指定库，原技能名保留，默认分类为仓库名，未选择项不会被自动部署。
2. **Given** 多技能仓库的默认分类已显示，**When** 用户修改分类名称并确认，**Then** 库中分类和展示的实际位置随之改变，来源仓库与上游路径仍可查看。
3. **Given** 仓库只包含一个技能，**When** 用户将其入库，**Then** 默认不额外创建仓库名分类。
4. **Given** 入库包含上游自带的管理资料，**When** 入库完成，**Then** 可看到已有标签、中文资料、支持声明及覆盖层；缺失支持声明按所属管理域内全支持处理。
5. **Given** 已开始一次模拟获取，**When** 用户查看进度或取消，**Then** 能看见进度及结果；取消情境不显示“入库完成”。本场景不据此确定正式下载实现或中途文件处理机制。

---

### User Story 2 - 整理管理层并部署使用 (Priority: P1)

用户在库中找到技能、理解原始内容，维护自己的组织信息和适配资料，然后选择本机 Agent 使用该技能。用户能看到库内原件、管理资料与部署结果的区别。

**Why this priority**: 最初提出的六项管理要求在这里共同发挥作用，这是区别于单纯下载工具的主要价值。

**Independent Test**: 载入已入库但未部署的预置技能，修改管理资料并部署，检查目标、适配内容与状态，不依赖来源获取流程。

**Acceptance Scenarios**:

1. **Given** 技能有中文短注释和正文译文，**When** 用户查看列表及详情，**Then** 原技能名保留，短注释帮助理解用途，正文默认中文并可切换原文；无译文时显示原文。
2. **Given** 技能有两个标签且位于某分类，**When** 用户修改标签并更换分类，**Then** 标签结果和实际目录位置可观察，分类最多一级；名称、标签、分类及预设筛选能找到对应技能。
3. **Given** 技能仅支持 Codex，**When** 用户选择部署目标，**Then** 不提供 ZCode 的可执行部署操作；预设批量部署也会过滤此目标。
4. **Given** 模拟电脑为 Windows，技能仅支持 macOS，**When** 用户查看库和尝试部署，**Then** 该技能整项变灰，不能部署，原因可读。
5. **Given** 技能有 Codex 专用覆盖内容及中文注释，**When** 用户部署到 Codex，**Then** 部署结果摘要显示选中的适配内容和注释，正文仍为原始正文，结果不携带 .manager；库内原始正文没有因注释改变。
6. **Given** 技能已部署到本机两个目标，**When** 用户在界面保存会影响部署的管理资料，**Then** 两个已有目标显示相应更新结果，没有新增部署目标。
7. **Given** Agent 已在库中维护译文或覆盖内容，**When** 原型模拟“Agent 维护完成并调用 CLI 同步”，**Then** 阅读资料或已有部署结果随之更新；原型不要求真实执行命令，也不新增 GUI 原始正文或脚本编辑器。
8. **Given** 某技能支持共享目录的全部读取目标，且目标可使用相同内容，**When** 用户选择共享目录部署，**Then** 能查看共享目标及通用内容结果；需要不同 Agent 内容的技能通过各自目标部署。此展示不表示实际 Agent 读取能力已验证。
9. **Given** 分类 A 的技能具有标签 X、Y，分类 B 的技能具有标签 Z，**When** 用户选择分类 A，**Then** 标签栏只展示 X、Y，不展示 Z；选择全部分类后展示 X、Y、Z。此规则同样适用于预设全库浏览及 Hermes 档案；没有标签的分类不显示其他分类的标签。

### User Story 3 - 吸收上游变化并保留自己的维护成果 (Priority: P1)

用户按来源仓库检查更新，了解已有技能的变化和新增候选，决定是否更新及哪些新增进入库。更新后的技能仍带着自己的管理资料，并成为自己的 SkillVault 维护成果。

**Why this priority**: 上游维护是用户明确指出的最重要链路，必须能从原型完整体验，而非只看到“有更新”标记。

**Independent Test**: 载入“已登记来源、已有部署、存在上游新版本”的情境，执行检查、查看、确认更新、选择新增，再检查库和部署结果。

**Acceptance Scenarios**:

1. **Given** 上游有一项内容修改、一项已入库技能删除和两项新增候选，**When** 用户检查全部，**Then** 可查看按仓库组织的变化、相关库及技能，以及新增、修改、删除的文件清单；检查本身不修改库。
2. **Given** 同一来源在编码库和龙虾库都有技能，**When** 检查并查看更新，**Then** 来源只显示一次仓库级检查结果，受影响的两库条目明确可见。
3. **Given** 用户尚未批准更新，**When** 用户查看变化后返回，**Then** 库内容与已有部署不变；单项确认只更新所选技能，仓库确认批量处理相关剩余变化，已更新到目标版本的条目不重复应用。
4. **Given** 本次有两个新增候选，**When** 用户批准其中一个入库并明确不入库另一个，**Then** 选中项进入库且不自动首次部署；再次检查时，明确拒绝项不再出现。
5. **Given** 上游不提供管理资料，本地已维护分类、标签、注释和覆盖层，**When** 更新上游内容，**Then** 本地维护成果保留；正文变更后原译文仍可阅读，并提示译文待更新。
6. **Given** 上游提供与本地同项的管理资料，**When** 用户批准更新，**Then** 同项采用上游值，本地额外添加而上游未提供的资料仍保留，目录分类不被上游重置。原型使用明确的预置项目示例，不推定正式资料合并格式。
7. **Given** 上游将已入库技能改名，**When** 用户查看变化，**Then** 显示删除旧技能、增加新技能，不展示自动改名迁移流程。
8. **Given** 已批准删除库中技能，**When** 更新完成，**Then** 对应受管部署被撤销；受管副本有外部修改的情境按照边界规则暂停该项。
9. **Given** 上游更新已完成，**When** 用户查看结果，**Then** 能看到库采用的新版本、管理资料处理结果、自己的库上传结果及已有部署更新结果，没有向来源仓库提交的操作。

### User Story 4 - 在另一台电脑继续使用同一技能库 (Priority: P1)

用户在一台电脑维护技能后，在另一台电脑获得相同的库内容与管理资料，继续使用和检查上游，同时保留每台电脑自己的部署选择。

**Why this priority**: 多电脑同步必须与上游更新分开，才能让用户清楚自己同步了什么、哪些 Agent 会受到影响。

**Independent Test**: 使用两个预置电脑情境，先在其中一个维护，再查看另一个同步后的结果；不连接真实远端，也不控制其他电脑。

**Acceptance Scenarios**:

1. **Given** Agent 在当前电脑维护完成，**When** 调用 CLI 同步已有部署，**Then** 本机部署更新但不直接上传；Agent 主动询问是否上传，用户同意后才模拟提交推送，未同意时本地成果与已有同步保留。
2. **Given** 另一电脑上传了技能内容、管理资料及预设变更，**When** 模拟启动、定时检查或用户主动同步自己的库，**Then** 无冲突变化自动进入本机库，更新已有部署，不弹出上游更新批准流程。
3. **Given** 两台电脑部署的 Agent 不同，**When** 库同步完成，**Then** 技能、管理资料、来源版本和预设一致，但各电脑部署目标及 Hermes 档案启用名单维持各自选择。
4. **Given** 同步内容包含新技能和“拒绝某上游新增入库”的决定，**When** 本机同步完成，**Then** 新技能进入库且未首次部署，拒绝项不再次提示。
5. **Given** 自己的库同步和外部上游更新同时可用，**When** 用户分别查看相关操作及结果，**Then** 能分辨哪个更新自己的维护成果、哪个需要审阅来源变化。
6. **Given** 模拟上传失败，**When** 用户查看失败原因并重试，**Then** 本地成果仍可查看，成功后显示库上传完成。原型不提供历史恢复或重新克隆流程。

### User Story 5 - 收编已有技能及接续 Agent 维护 (Priority: P1)

用户在本机 Agent 的技能列表发现未受管技能，将其纳入 SkillVault 并接管原有部署；以后让 Agent 在库中维护并同步已有部署。自建技能也可直接由 Agent 创建到库中。

**Why this priority**: 用户明确需要接管现有安装，尤其是龙虾技能；这条链路应让用户知道管理权如何进入 SkillVault。

**Independent Test**: 载入本机已有未受管技能的情境，通过收编入口完成管理接管，模拟 Agent 修改后的同步结果。

**Acceptance Scenarios**:

1. **Given** Agent 中有一个未受管技能，**When** 用户点击收编入口并确认对应库，**Then** 技能进入 SkillVault，原有安装成为受管部署，无需再部署一次，状态由“仅本地”变为受管且已同步。
2. **Given** 用户选择多个未受管技能，**When** 批量收编，**Then** 可逐项看到入库和接管结果。
3. **Given** Agent 在库中修改了已部署技能，**When** 模拟其调用 CLI 同步，**Then** 已有部署显示最新内容，不需要用户回 GUI 补做部署。
4. **Given** 用户只让 Agent 创建一个自建技能，**When** 模拟创建完成，**Then** 技能仅进入库；用户后续明确要求部署时才新增部署。
5. **Given** 用户选择删除未受管本地技能，**When** 执行模拟删除，**Then** 该项从 Agent 清单移除，不改变其他库技能。受管项撤销部署后库中原件保留。

### User Story 6 - 让龙虾技能进入 Hermes 档案使用 (Priority: P1)

用户将龙虾库技能部署到本机 Hermes default（默认档案）技能池，然后决定哪些其他档案启用它。

**Why this priority**: 多档案技能使用是用户强调的重点，必须能与入库、收编和同步主线连接。

**Independent Test**: 从龙虾库已有技能、default 有可用候选和两个档案的情境开始，完成部署、单项或批量启停，并核对其他档案状态。

**Acceptance Scenarios**:

1. **Given** 编码库中的技能尚未进入龙虾库，**When** 用户尝试提供给 Hermes，**Then** 不能直接部署；复制进入龙虾库后可按该库支持范围决定部署。
2. **Given** 用户复制技能到另一库，**When** 复制完成，**Then** 原件保留，新条目包含管理资料及来源关系，两份独立维护且复制不自动部署。
3. **Given** 龙虾库技能首次部署到 default，**When** 部署完成，**Then** 其他档案能看到可选候选，但不自动新增启用项。
4. **Given** 两个档案有不同启用名单，**When** 用户在一个档案中多选并启用或禁用，**Then** 只改变该档案，既有其他选择保留。
5. **Given** 某档案原有未受管的独有技能处于启用状态，**When** 用户收编，**Then** 技能进入龙虾库并部署到 default，原档案启用状态保留。
6. **Given** 用户选择不同档案查看技能，**When** 界面切换，**Then** 只改变查看和管理对象，不表示切换 Hermes 活动档案。
7. **Given** 用户在档案中浏览技能，**When** 点击名称或内容区，**Then** 显示与技能库一致的只读详情与文件目录树，管理编辑需明确前往技能库；所有档案共用同一份内容，不在档案内维护正文和管理资料。未收编项提供收编入口。

---

### User Story 7 - 用预设复用技能组合 (Priority: P2)

用户将常用技能组成预设，按组增加或撤销部署，并通过预设筛选找到相关技能。

**Why this priority**: 预设让重复部署更省事，但可在单技能流程已清楚的基础上验证。

**Independent Test**: 使用已有技能和两个有重叠成员的预设，修改组合并执行部署、撤销和筛选。

**Acceptance Scenarios**:

1. **Given** 某 Agent 已有 A、B，预设包含 B、C，**When** 用户部署预设，**Then** 最终为 A、B、C，不移除已有 A。
2. **Given** 同一 Agent 有 A、B、C，预设包含 B、C，**When** 撤销该预设部署，**Then** 只剩 A；B 即使属于其他预设也被撤销，库中技能保留。
3. **Given** 用户编辑预设成员，**When** 保存组合，**Then** 不自动改变实际部署。
4. **Given** 某成员不支持目标 Agent 或当前系统，**When** 批量部署预设，**Then** 该项被过滤且可查看原因，其他适用成员完成部署。
5. **Given** 两库分别维护预设，**When** 用户筛选或查看成员归属，**Then** 只使用对应库成员，同一技能可属于多个预设，预设不改变技能目录分类。

### Edge Cases

这些情境只用于验证已确定的行为，不要求构建新的恢复或防护体系。

- 无译文：详情直接显示原文，不提供一键翻译。
- 未声明支持范围：在对应管理域内默认全支持。
- Agent 不支持或当前系统不适用：分别限制目标及整项部署，说明原因。
- 部署遇到未受管同名技能：按既定规则直接覆盖并接管，不增加冲突检查步骤。
- 受管部署副本被外部修改：显示“本地有变更”，暂停该技能覆盖；其他技能继续，由 Agent 检查、用户裁决，不提供专门差异合并界面。
- 自己的库有同步冲突：暂停库同步并提示处理方向，不出现新构造的自动合并流程。
- 远端暂不可用：显示原因，本地库管理和部署仍可体验；远端恢复后可重试，不提供“断开并删除远端配置”操作。
- 上游存在删除或改名：以明确变更清单确认，不自动匹配名称或迁移管理资料。
- 上游检查无变化：数量与实际清单一致，重复检查不制造新的更新结果。
- 首次入库未选择的技能与后续新出现的技能要区分；本次原型不追加“重新发现所有历史未选项”的产品流程。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 原型必须允许用户完成故事 1—7 的完整操作链路；每个主要动作都具有可观察的前后状态及结果，不以只有点击样式变化的按钮代替业务结果。
- **FR-002**: 原型必须明确标示模拟环境，不实际访问来源仓库、读写真实 SkillVault、部署文件或执行安装命令；可以通过“原型情境”控制切换电脑、系统、上游版本和外部改动。
- **FR-003**: 默认进入技能库，编码与龙虾库分开浏览；原型需支持搜索、分类、多个标签、预设及部署目标筛选，并可切换列表或网格。选择某个分类后，标签栏只展示该分类下技能实际拥有的标签；选择全部分类时展示当前页面候选技能的全部标签。分类与标签联动同样适用于预设全库浏览和 Hermes 档案，不改变技能管理资料或成员／启用状态。具体导航及布局由设计验证。
- **FR-004**: 来源入库在同一页面完成：仓库地址、管理域、分类和技能预览选择同时可见，预览在下方展开；可直接修改来源并重新预览，不跳到替代输入页的下一层。用户选择子集、修改默认分类并确认入库；更改来源后不得把旧预览当作新来源入库。获取进度、取消和结果可观察，技能原名不变。
- **FR-005**: 每个上游技能必须能查看来源仓库、分支、上游路径、采用版本、库内位置及部署位置，详情提供附带文件清单，以目录层级区分文件夹、文件和归属关系，支持点击阅读。更换来源通过重新导入表达，不新增来源重绑入口。 文件与部署列出本机相关 Agent 目标，已部署亮显、未部署灰暗，不增加此处的档案分配管理。
- **FR-006**: 用户必须能维护多个标签、一级目录分类、中文短注释及 Agent 和系统支持范围；变更后列表、详情、筛选和适用目标一致。分类变更必须反映实际目录位置。
- **FR-007**: 原型必须展示中文正文与原文切换，存在译文时默认中文，保留原技能名；中文注释通常不超过 20 字，但不新增强制长度拦截或独立中文显示名。
- **FR-008**: 原型必须让用户查看按 Agent 和系统适配的覆盖内容，以及选择目标后的部署结果摘要；译文和覆盖内容可使用预置的 Agent 维护结果模拟，不强制引入尚未确认的编辑器。
- **FR-009**: 部署及新增启用必须遵守管理域、Agent 和当前系统支持范围；系统不适用的技能灰显并禁止部署，保存后的声明跨重新打开生效。支持声明收窄不自动撤销已有部署或档案记录，应显示不适用警告，仍可手动撤销或禁用。
- **FR-010**: 单项、多项及预设部署必须可体验；新增部署只有在用户明确要求部署时发生。结果包含原始内容、适用覆盖内容和中文注释，不包含 .manager 或阅读译文。
- **FR-011**: 原型必须体现库内维护与部署副本的区别；GUI 保存部署相关资料后自动更新已有部署，模拟 Agent 编辑后由其调用 CLI 同步，均不得自动新增目标。
- **FR-012**: 上游检查必须按仓库组织，展示已有技能变化、新增候选、涉及的库及文件变化；同一来源不因进入两库而重复检查。支持模拟启动检查、手动检查全部及周期检查。
- **FR-013**: 检查上游不得应用内容；支持用户明确确认后的单技能更新和仓库批量更新。单项只处理所选库内条目，不改变其他条目或新增候选；批量处理仓库剩余已有技能更新、删除及选定新增。按技能记录采用版本，GUI／CLI 同规则，自维护 Gitea 来源同样显式确认。
- **FR-014**: 原型必须区分新增候选与首次从新来源安装技能；允许选择新增入库，并记住明确不入库的决定，后续检查和另一电脑同步后不再提示拒绝项。
- **FR-015**: 上游更新结果必须体现本地管理层保留规则：分类保留；上游未提供项目保留本地值；上游提供同项时采用上游值。原文变化后原译文保留并提示待更新。
- **FR-016**: 来源仓库只作为获取来源；原型不得提供回推来源仓库的操作。更新后的技能、管理资料及来源版本一起成为自己的 SkillVault 维护成果。
- **FR-017**: 自己的库具有独立于上游更新的同步语义；无冲突拉取静默应用。Agent 维护后由维护 Skill 主动询问每次改动是否上传，未明确同意不得提交推送；保存及 CLI 同步部署不等于上传授权，其他同步动作不得顺带上传未获同意改动。
- **FR-018**: 两个电脑情境必须共享技能、管理资料、来源记录、预设和拒绝新增的决定；保留各自部署记录与 Hermes 档案启用名单，新到库技能不自动首次部署。
- **FR-019**: 原型必须提供库同步失败原因、重试上传及同步冲突提示；保留本地管理体验，不添加历史恢复、重新克隆或复杂合并界面。
- **FR-020**: Agent 技能列表必须显示受管标识、“已同步”“仅本地”“本地有变更”；未受管项提供快速收编，单项或批量收编同时入库并接管原有部署。
- **FR-021**: 未受管本地技能可以模拟单项或多选删除；受管技能可以撤销部署并保留库内技能；删除库内技能须撤销其受管部署，有外部修改的项按既定暂停规则处理。
- **FR-022**: 模拟 Agent 自建技能必须遵循“只创建则只入库”；模拟正式维护在库中完成并调用 CLI 同步已有部署，不要求实现 CLI 命令语法。 同库内创建、入库、收编和复制遇到同名时必须提示并阻止，不覆盖或复用原条目；跨域库同名规则保留。
- **FR-023**: Hermes 技能使用必须遵循“龙虾库 → default 候选池 → 各档案明确启用”；新候选不自动启用其他档案，可单项及多选启停，选择档案不切换活动档案。
- **FR-024**: 档案独有未受管技能收编后必须进入龙虾库、部署到 default，并保持原档案启用状态；不添加多实例、档案生命周期或 SOUL.md 指令管理。
- **FR-025**: 库间复制必须保留原件、管理资料和来源关系，两份独立维护，不自动部署；同一来源的更新结果同时关联两库受影响条目。
- **FR-026**: 两库预设独立，成员来自各自库，同一技能可加入多个预设；编辑定义不改变部署，部署按组增加，撤销按成员执行，不引入唯一当前预设或部署来源追踪。
- **FR-027**: 原型必须能让用户验证符合通用内容条件的共享目录部署；按既定产品假设处理读取范围，不要求逐 Agent 读取声明，也不得将模拟状态描述为实际读取能力已验证。
- **FR-028**: 本轮必须使用简体中文界面及原技能名；整体沿用 FeiSkillDock 的界面风格，保留现有桌面外壳、密度、配色和控件形态，依照新业务调整流程与入口，不进行整体视觉重设计。中文注释、状态和文件变化必须清楚可读；具体视觉基线见 [视觉参考](visual-reference.md)，其尺寸和布局可经原型体验调整，不要求像素级复刻。
- **FR-029**: 主流程、失败及边界情境必须有明确的起始入口，原型提供恢复预置情境的体验方式，以便重复评审；这仅是原型控制，不代表正式产品有历史恢复功能。
- **FR-030**: 原型必须允许从结果继续后续步骤，例如从入库结果进入维护和部署、从上游更新结果查看库及部署状态；不得要求用户理解源代码或旧版裁决编号。
- **FR-031**: 设置页保留 Agent 检测、已检测／其他支持 Agent 分组与重新检测；内置目录资料全量沿用。技能目录和项目相对路径可行内修改、取消及恢复默认。沿用旧版卡片、启停、拖动排序与分区配置行，新配置使用相同风格；所有检测、目录与桌面行为仅模拟。
- **FR-032**: 库页和预设技能卡片保留三点菜单，包含复制到另一库、移动分类、添加标签和删除；预设成员开关独立。添加标签可选已有或输入新名称，保留原有标签并去重。有上游变化的技能提供单项更新预览与确认，不自动更新同仓库其他技能。
- **FR-033**: 可针对单个或多选技能生成并复制外部 Agent 的维护任务说明，包含用户要求、库内路径、当前管理资料及已有部署概况，并附既定维护与上传询问约定。生成本身不维护、部署或上传，不引入内置 Agent。
- **FR-034**: 单技能上游变化允许跳过当前版本，保留现有内容和部署，退出当前待更新提醒及批量更新范围；下个版本重新提醒。提供已跳过版本查看、恢复提醒和明确更新入口；决定随库同步，CLI 能查询及操作，与新增候选拒绝入库分开。
- **FR-035**: 工具中心必须提供本机工具清单与搜索／分类／状态筛选；详情包含概览、维护指南、配套 Skill、版本与更新。概览有独立工具简介及调用入口、安装资料。单项／全量版本检查由本项目负责，实际安装／更新及指南编写交给外部 Agent，可生成复制维护任务。配套 Skill 必须展示具体候选后选择入库，纳入既有技能库规则，入库不自动部署。原型中的检查及 Agent 回报均明确模拟，不能冒充真实操作。

#### 交互原型的体验范围

交付可操作原型及简明的体验说明。设计者可自行决定信息组织方式，但应让用户找得到以下业务信息与动作：

| 业务位置 | 用户需要完成的事情 |
|---|---|
| 编码／龙虾技能库 | 搜索筛选、分类标签、阅读中文与原文、维护管理资料、查看来源与部署情况 |
| 来源获取 | 查看仓库技能、部分选择、修改分类、体验进度及入库结果 |
| 上游变化 | 按仓库看技能和文件变化、批准更新、选择新增、记住不入库决定 |
| 本机 Agent 技能 | 查看受管状态、部署／撤销、收编、删除未受管项 |
| 自己的库同步 | 分辨自己的维护成果同步与上游更新，查看上传、拉取及已有部署结果 |
| Hermes 档案 | default 候选、各档案启用名单、批量启停及档案独有技能收编 |
| 预设组合 | 维护成员、按组部署／撤销、筛选查看归属 |
| Agent 指令文件 | 沿用旧界面编辑全局和工具专属指令，保存自动拼接并模拟分发 |
| 工具中心 | 查看本机工具、版本检查、Agent 维护指南与任务、配套 Skill 入库 |
| 设置 | Agent 检测分组、启停与目录修改；原有配置及新库同步配置沿用统一样式 |

这些是信息与操作需求，不强制“一行对应一个独立页面”。原型不增加独立首页或项目专属管理；工具中心按新增专题提供实际可操作原型。本轮不制作真实登录、Git（版本管理）认证、设置中心全集或安装市场。

#### 预置情境与资料

以下名称及版本均为虚构资料，仅供原型可重复体验，不代表真实仓库、安装检测结果或设备管理能力。

| 情境 | 预置内容 | 需要观察的结果 |
|---|---|---|
| 部分入库 | demo-tools 初始包含 web-check、repo-audit、mac-notes，选择其中两个 | 部分入库、仓库名默认分类、保留来源、尚未首次部署 |
| 支持与适配 | web-check 支持 Codex 和 ZCode，有 Codex 覆盖内容；mac-notes 仅支持 macOS | 目标过滤、系统置灰、目标适配结果及中文注释 |
| 上游新版本 | 已入库 web-check 修改正文和脚本；repo-audit 删除；新增 page-export、tab-scan | 内容修改、删除、文件清单、选择一项新增并拒绝另一项 |
| 自带管理资料 | personal-demo 单技能来源带中文注释和标签，新版本提供新注释；本地另有翻译和覆盖内容 | 单技能不自动分类、继承上游资料、同项采用上游值、额外本地资料保留 |
| 两库同源 | web-check 已复制到龙虾库，两份有各自维护的管理资料 | 一次来源检查、清楚列出两库影响 |
| 两电脑续用 | 电脑 A 为 macOS 并已部署 Codex，电脑 B 为 Windows 并已部署 ZCode，Hermes 档案名单各机不同 | 共享库内容与自己的部署选择分开，Windows 情境验证 macOS 限制 |
| 本地收编 | Agent 有未受管 local-backup，某 Hermes 档案已有该技能且已启用 | 收编接管，进入龙虾库及 default，保留原档案启用状态 |
| 组合使用 | 两个编码预设有重叠成员，另有独立龙虾预设 | 按组增加／撤销、不追踪来源、定义编辑不改变部署 |
| 外部改动或故障 | 一项受管副本有变更、一次库同步冲突、一次上传失败 | 暂停范围准确、显示处理方向、可体验重试 |

每个情境可独立开始，也应提供一个连贯演示：部分入库 → 维护管理层 → 部署 → 模拟上游新版本 → 确认更新及新增 → 模拟提交上传 → 在另一电脑同步并查看已有部署。失败情境通过预置资料进入，不要求实现真实故障检测。

### Key Entities *(include if feature involves data)*

- **技能**：按所属编码或龙虾库独立维护的能力，具有原名、内容、文件清单、分类和来源关系。
- **管理层**：技能自己的标签、中文阅读资料、短注释、Agent 和系统支持范围、覆盖内容；与原始内容一起形成维护成果。
- **来源仓库**：多个入库技能共同的获取来源，具有上游路径关联、当前采用版本、检查结果及新增选择记录。
- **SkillVault**：统一维护与提交的自己的库，承载技能、管理层、来源关系及预设；远端用于跨电脑同步。
- **本机部署**：技能在指定本机目标的安装结果及状态，独立于跨电脑共享的库内容。
- **Hermes 档案**：同一本机 Hermes 根目录下各自的启用名单，使用 default 技能池候选。
- **预设**：所属库内可复用的技能组合，定义共享，执行部署与撤销时改变本机目标。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在一次原型评审中能操作完成故事 1—7；七条流程均具有可观察的最终状态，主流程没有停在不可继续的静态占位页。
- **SC-002**: 完成连贯演示后，用户能正确说明“入库”“首次部署”“上游更新”“自己的库同步”四项操作的不同结果，四项均能在原型中找到对应动作与状态。
- **SC-003**: 用户能找到并体验六项管理能力；六项均具有对应的资料或操作结果，其中中文正文和原文能切换，原技能名保持不变。
- **SC-004**: 在两电脑情境中，共享的技能内容、管理资料、来源版本、预设与拒绝新增决定全部一致；部署及档案名单全部保留各自选择，未经首次部署命令新增的部署数为零。
- **SC-005**: 上游更新演示中，能明确辨认一项内容修改、一项删除和两项新增；只选一项新增后，入库数为一，拒绝项在下一次检查中提示次数为零。
- **SC-006**: 本地管理资料保留、自带管理资料更新、系统不适用、受管副本变更及库同步冲突五种情境，全部显示与本规格一致的结果，无隐藏覆盖或模糊成功提示。
- **SC-007**: 用户可以重新载入预置情境重复体验全部主流程；评审结束后，记录哪些操作理解正确、哪里停顿、有哪些新增业务需求，作为下一轮规格修订输入。

## Assumptions

- 用户在 2026-10-15 决定直接在当前项目中迭代交互原型，不再把 openDesign 交接作为前置步骤；正式软件实现仍是后续阶段。
- 原型面向个人桌面使用情境，使用虚构库、来源、Agent、档案及电脑状态；真实访问、Git 操作、文件部署及命令执行属于后续正式产品实现。
- 当前提供可双击打开的单 HTML 文件，使用浏览器本地保存的模拟资料；此原型形式不限定正式产品的技术栈。
- 用户已明确整体界面风格不准备大动；沿用旧版视觉语言，不因此恢复已移除入口或旧业务规则。视觉参考与原截图已保存在本功能目录中，用于直接迭代原型。
- 用户没有要求 GUI 原始正文和脚本编辑器，也未确定译文与覆盖层编辑器。原型暂提供中文译文编辑、覆盖文件示例添加／移除，以及模拟 Agent 提供维护结果和观察部署变化；这些交互不据此固化为正式编辑器需求。
- “维护完成”与上传授权分开：Agent 任务保存及 CLI 同步后仍须主动询问是否上传，未同意不提交推送；具体命令和底层同步实现留到设计。模拟询问不引入首版内置 Agent。
- 上游检查周期采用已经确认的关闭、30 分钟、1 小时、6 小时、24 小时，默认 1 小时；原型可模拟检查触发，不必等待实际周期。
- 预置情境中的电脑／系统切换与重置仅服务于原型评审，不引入正式产品的设备管理、远程部署或历史恢复功能。
- Agent 指令编辑与保存自动拼接分发已按用户要求加入原型，界面沿用旧版。主题字号、托盘及日志等已有范围不因原型模拟或省略而移除。工具中心按 2026-10-15 新增专题恢复原型讨论；项目专属技能管理继续后置。
- .manager 与来源记录格式、覆盖层维度组合和合成顺序仍属于后续设计问题；原型只表达已确认的输入、目标差异和结果，不据此制定内部存储方案。
- 原型设计以本规格为主；[项目宪章](../../.specify/memory/constitution.md)提供原则，[需求记录](../../docs/requirements.md)提供访谈背景，[当前范围记录](../../docs/legacy-skill-capabilities.md)提供旧版能力对照。后两者不能整表当作强制规格。

## 当前原型评审入口（2026-10-15）

[index.html](ui-prototype/index.html) 可直接打开。顶级导航保留技能库、龙虾技能库和 Hermes 档案，移除重复的独立“预设”项；预设分组标题、预设名称与新建按钮仍可进入管理。

原型操作相互连贯：入库、管理资料保存、部署／撤销、收编、仓库变化处理、预设组合、档案启停和自己的库同步共用模拟状态。底部“原型试玩”提供引导演练、其他电脑提交、系统切换、远端不可用和冲突情境。所有结果为模拟数据，浏览器本地存储支持刷新及重新打开后继续；明确重置才恢复初始资料。

当前是待用户操作评审的原型，不代表全部验收场景已获用户认可。实际 Git 下载进度、认证、CLI、托盘与定时后台任务均未实现；相关需求不因模拟或未实现而移除。

### 预设交互调整（2026-10-15）

用户要求预设页面保留分类效果，并沿用旧版的全库浏览方式：进入某个预设时展示所属技能库的全部技能，通过卡片右上角开关将技能加入或移出该预设。原型提供分类、标签、搜索及“全部／已加入／未加入”筛选；移除独立的添加成员弹窗。新建预设后进入同一页面选择成员。

开关只调整当前预设组合，不自动改变实际部署；部署和撤销仍由独立动作执行。分类沿用技能所在目录，不创建预设专属分类。此处记录本轮体验后的交互方向，不将具体布局固化为正式产品实现约束。

### Agent 指令界面沿用（2026-10-15）

用户要求保留旧版“Agent 指令文件”界面，不另行设计。左侧固定全局项及可搜索的工具列表，右侧单编辑区，底部一个保存按钮。切换工具保留当前草稿，保存全部源内容后保持弹窗打开；自动将全局与各工具专属内容拼接为对应目录的 `AGENTS.md`。原型可体验不同工具的独立专属内容、只有全局、只有专属和清空内容的保存结果，不需要额外选择分发目标。

源内容仍在 SkillVault 维护和同步，分发到本机对应工具目录。网页仅模拟写入；当前示例指令目录使用旧版工具目录资料，与技能目录独立，修改技能路径不隐式移动 `AGENTS.md`。正式路径仍须按工具实际目录核对。本项不增加 Hermes 档案 `SOUL.md` 管理。

### 设置页沿用（2026-10-15）

用户最新要求保留 Agent 检测，替代此前移除检测的暂定范围。原型按旧版 53 项内置资料提供已检测／其他支持 Agent 分组；初始电脑 A 模拟检测 8 项、启用 6 项，重新检测显示忙碌状态及模拟结果。启停只改变本机管理入口，不启动或卸载 Agent，也不删除已有部署副本。卡片支持直接拖动排序，路径行悬停显示铅笔，保存后相关页面显示新技能路径，取消和恢复默认均可体验。

设置继续采用旧版分区面板、紧凑配置行和分段按钮，SkillVault 同步等新增配置保持同一视觉语言。验收时可修改／取消／恢复 Codex 技能目录及项目相对路径，调整启停与顺序，再检查侧栏、Agent 路径和指令结果；已有部署记录不因启停被清空。上述操作均为本机模拟状态，不随模拟 SkillVault 同步；实际目录迁移与真实安装检测尚未实现。

### Hermes 档案浏览样式

用户要求档案内保留分类与标签，界面与技能库相近。原型采用顶部标签筛选、左侧分类栏及右侧技能卡片；分类、标签、搜索和已启用／未启用条件可以组合使用。受管技能沿用库内分类和标签，不另建档案专属分类或标签；未收编的档案本地技能仍可从未分类、无标签中找到。保留档案切换、单项与批量启停以及收编流程。

### 原有界面细节与直接操作

用户要求预设管理操作放在左侧：行内拖动排序、重命名和删除，不在主页面另设编辑或排序。技能卡片通过左上角手柄直接拖动，不使用专门的排序弹窗。原型中的排序仅改变显示次序，不移动分类目录、不改变预设成员或实际部署。

用户补充沿用旧版预设图标选择。创建及重命名预设时提供原有图标网格，名称不变时也能单独保存图标修改；图标作为组合定义随库保存，在侧栏、总览及预设标题中一致显示，不影响成员与部署。

用户进一步要求主动核查旧界面的其他细节，不依赖用户逐项发现遗漏。[交互细节核查](ui-interaction-audit.md)记录源码事实、当前原型差异及处理状态。研究结论不整表转成强制业务规格；已移除功能不因其界面细节被借用而恢复。

验收：从预设卡片菜单添加已有及新标签，原标签与成员不变；移动分类后已有部署、来源和成员不变；复制与删除沿用既定规则。对同仓库 A、B 中的 A 单项更新，只有 A 内容、采用版本与已有部署变化，B 和另一库副本的更新提示、新增候选及忽略记录不变；随后仓库更新只处理剩余变化，不重复应用 A 的版本。单项上游删除须展示移除影响，经确认后处理。


### 六项维护裁决与系统限制（2026-10-15）

以需求记录“六项裁决与系统限制”为准：Hermes 档案只管理使用，共用技能内容且详情只读；整份正文被覆盖层替换属于操作者的明确结果；Agent 每次修改后由维护 Skill 主动询问是否上传；部署目标亮暗显示，不在技能详情管理档案；同库重名提示并阻止；不适用已有部署保留并警告。

验收补充：在 Mac 情境将一个已部署技能声明为只支持 macOS，并收窄到某个 Agent，原有部署仍在，其他目标出现警告；刷新、关闭网页再打开并切换 Windows，该声明仍在，技能灰显且单项／批量部署被禁止。Agent 修改后调用 CLI，已有部署更新但远端版本不变；选择不上传后，刷新和其他同步动作仍不上传；明确同意才上传，下一次修改须再次询问。重名创建、入库和收编不得覆盖原内容。档案详情可读，编辑入口明确回到库中。

### 更新列表返回与变化分层（2026-10-15）

更新及新增的“查看并决定”必须能返回仓库列表，保留原查看范围、当前选择和分类草稿。返回不应用更新或忽略候选；确认才应用，并回到剩余仓库列表。仓库标题、版本、技能名、状态和变化文件应有明确视觉层级，不能都用同一段文字表达。单技能更新保持既定范围，使用相同版本及变化文件样式。

验收：从新增列表进入某仓库，勾选一项并修改分类，返回后库无变化；再次进入草稿保留；确认后选中项入库、未选项按既定规则忽略，回到新增仓库列表继续处理。更新入口同样可往返，检查全部不丢弃本轮草稿。

### 外部维护任务与版本跳过（2026-10-15）

本轮仅采纳外部 Agent 任务说明与跳过当前上游版本；整理状态扩展筛选、页面工作位置记忆暂不做。具体语义见需求记录同名章节。维护说明使用选定技能的当前资料快照，用户可写明期望修改，实际文件由外部 Agent 读取；维护 Skill 必须继续执行每次修改后询问是否上传的规则。原型只生成说明，不运行维护。

验收：单项／多选生成说明只包含指定技能，输入要求后说明更新，库与部署不变；说明包含路径、管理资料、CLI 同步已有部署及上传询问约定。跳过 A 的当前版本后，刷新仍不提醒，B 的更新和新增候选不变；仓库更新只应用未跳过项。已跳过列表可查看／恢复／明确更新，下一上游版本再次提示。仓库决定页进入单技能页后仍能返回，保留分类与新增选择草稿。


### 工具中心需求确认（2026-10-15）

用户要求按当前原型登记需求，包含后续补充的配套 Skill 候选列表及完整工具简介。以需求记录“工具中心：已确认需求”为完整业务描述：本机工具可见、软件查版本、外部 Agent 实际维护、安装时生成指南、配套 Skill 选择后入库。当前卡片、四个详情分区及相关操作作为已确认交互方向；具体像素、资料格式及实现方式仍可调整。

验收场景：

1. 从本机清单搜索／按分类与状态筛选，进入详情与返回；概览有工具简介，能了解是什么、用途和场景，并找到入口与安装资料；维护指南单独可读。
2. 单项／全部检查显示上游版本及检查结果；失败、缺检查来源、未检查不伪装成最新，检查不改变本机安装版本。
3. 复制安装／更新／指南维护任务时包含相应资料与约定；生成任务不代表执行。Agent 实际操作与验证后回写，工具更新不自动改变配套 Skill 或部署。
4. 配套 Skill 入库页同时展示来源、候选原名、中文注释、用途和勾选状态，显示数量；没有选择时不能确认，重新勾选保留已填资料。选择管理域及管理资料后仅所选项入库，保留来源、禁止同库重名，不自动部署。
5. 安装／登记要求 Agent 生成维护指南；原型只通过明确标注的模拟回报体验结果，不把演示表单设为正式用户维护必经步骤。

当前不确定而保留后续讨论的边界：工具资料与本机安装记录如何跨电脑同步、自动发现与登记、后台检查时机／频率、版本源适配、真实 Agent 回写接口、启动／激活方式。这些不因确认当前原型被推定为已解决。全部原型操作不访问真实工具或网络。
