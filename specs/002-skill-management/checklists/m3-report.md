| 检查 | 命令 | 结果 |
|---|---|---|
| 入库同域同名（大小写不同：库内 `Existing`，上游 `existing`） | `skill import ... --skills existing --uncategorized` | 阻止，退出码 1，消息"同一管理域已存在同名技能：code/existing"，**未入库** |

## 六、遗留与偏差（如实记录）

1. **T031 / T040 / T041 未保留"先失败"的红灯证据**：这三个测试文件是在核心/CLI 已实现后编写并跑通的，与 tasks.md "测试先于对应实现编写，确认失败后实现"的要求有偏差。测试本身有效（覆盖了要求的断言），但不能声称走了 red→green 流程。
2. **GUI 侧 SC-008 已在 T123 补验通过**（见末节）；`update --to`、复制对话框、重新预览保留勾选的历史点按缺证据仍保留。
3. **`--to` 指向非最新历史提交**的按 OID 浅获取：本地 `file://` 场景未实测（远端可能拒绝按 SHA 浅获取，届时如实报错）。
4. **新增候选的资料补充项**受 CLI 契约限制（见第三节），待 T090 统一。
5. **`include-new` 在技能使用非默认 `ref` 时按远端 HEAD 获取**：已知取舍，未新增机制。
6. `update`/`update-repo` 在"内容已合并但部署同步暂停"时返回非零并在消息中同时说明两者，不把内容更新标为成功项。
7. 本地路径（非 `file://`）克隆时 git 忽略 `--depth` 且不产生进度输出——这是 git 自身行为，非实现缺陷；进度验证需用 `file://` 或真实远端。
8. 启动时/定时自动检查属 M4（T053），本期未接入。
9. 未执行 `git commit` / `git push`。
