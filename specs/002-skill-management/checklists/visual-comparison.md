# 逐张视觉对照：实现界面 vs 交互原型效果图

对象：`specs/001-skill-management-prototype/ui-prototype/renders/` 全部 **46 张**效果图（统一 1720×1040）。
方法：同一窗口尺寸下运行打包后的 `.app`（`com.fei.skillmanager`），逐张截图与效果图上下拼接对照；
同时用源码度量做数值核对（字号/间距/控件尺寸），避免只靠肉眼判断。
对照图证据在 [evidence/visual/](evidence/visual/)（`vis-NN-*.jpg`，每张上为原型效果图、下为实现截图，等比缩放后各占一半）。

**事实基础（先排除整体缩放）**：

- 本机显示为 2560×1440、`UI Looks like 2560×1440`（无缩放）；应用窗口配置 `1720×1040`（`src-tauri/tauri.conf.json`）。
- 本机应用状态库里只有 `vault_path` 一条设置，**没有 `font_scale`**，即整页 zoom = 默认 1（`src/lib/appearance.ts:14-19` 的 `zoom` 机制未被启用）。
- 因此"元素大小不一样"不是整体缩放造成的，只能来自逐元素差异。
- 实测窗口 bounds 为 `1720×958`（高度比配置少 82px），原因未查明（无 Rust 侧 `set_size`、无窗口状态持久化插件、无 Saved Application State）。后果是竖屏内容比效果图少约一行，不影响元素尺寸对比。
