# Feature Specification: Skill Manager 正式产品

**Feature Branch**: 功能分支未创建；2026-10-15 质检时项目已初始化 Git，当前为 `main`，已配置 GitHub `github` 与 Gitea `origin` 远端。本功能按目录 `002-skill-management` 组织。

**Created**: 2026-10-15

**Status**: Draft — 依据需求记录与项目原则整理的正式产品规格；标注"留待设计"的事项在实现规划阶段处理。

**Input**: 用户指令"进入正式产品需求定义"。依据 [需求记录](../../docs/requirements.md) 的已确认结论、[项目原则](../../.specify/memory/constitution.md)（v2.0.2）与 [ADR 0001](../../docs/adr/0001-library-and-local-state.md) 整理。

本规格定义 Skill Manager 第一版正式产品的行为与验收边界，覆盖技能库维护、技能获取、部署、预设、Hermes 档案、上游更新、跨电脑同步、Agent（代理）接入与指令、工具中心。`specs/001-skill-management-prototype` 是交互原型规格，其模拟数据与演示实现不代表本规格的实现方式。规格只定义"做什么与验收什么"；字段格式、命令语法、存储布局与合成算法留待实现规划。界面语言仅提供简体中文。

## 业务关系与阅读示例

术语定义以 [GLOSSARY.md](../../GLOSSARY.md) 为入口；以下用已有需求解释容易混淆的关系，不增加新的使用流程。

| 对象 | 在本项目中的职责 | 与其他对象的关系 |
|---|---|---|
| Skill Manager 项目仓库 | 保存软件源码、文档及配套维护 Skill 的技能源文件 | 不是用户的 SkillManagerVault；其中的维护 Skill 可作为普通上游技能入库 |
| 用户的 SkillManagerVault | 保存用户统一维护的技能及共享资料 | 一个逻辑库，各电脑各有本地克隆；编码库和龙虾库是同库内两个管理域 |
| 某技能的上游仓库 | 提供该技能的原始来源和后续版本 | 可以是用户自己维护的仓库；上游更新按来源关系进入 SkillManagerVault |
| 本机部署目标 | 保存按目标/系统合成的使用副本 | 包括 Agent 目录、共享目录及 Hermes default；部署记录留本机 |

**一条完整主线**：电脑甲从上游 B 选择技能进入 SkillManagerVault，维护管理资料并部署给本机 Agent；后来明确采用 B 的新版本，再把自己的 SkillManagerVault 上传。电脑乙拉取的是同一个 SkillManagerVault，直接得到已采用的内容、管理资料和来源记录，不重新导入 B、不再批准同一次采用，也不因甲的部署而首次部署；乙只刷新自己的已有部署。两机系统或目标不同，部署产物可以不同，库内资产仍一致（FR-001/012/019/029～038）。

**“同步”须看对象**：上游检查只报告来源变化，应用上游更新要明确采用；SkillManagerVault 拉取传播已维护成果，无冲突时静默应用；`deploy sync` 只刷新本机已有技能副本，不上传库。GUI 保存与外部 Agent 修改后的上传路径按 FR-038 区分；已获同意的上传失败可由用户主动重试，后台路径不提交或推送。

**库中维护与使用副本分开**：分类移动不改变技能身份；跨域复制产生两份独立维护的库条目，保留上游关系但不互相同步。阅读译文不是部署正文，中文注释和覆盖层仅在合成时进入副本；支持声明限制目标，Agent 检测只说明本机环境，二者不能互相替代（FR-003～008/014～021/041）。

**“后来新增”与“未入库”分开**：首次来源中已有 A、C，用户只选 A，未选 C 不表示明确拒绝，也不因此把 C 当作后来新增；以后来源中新出现且当前仍存在的 B 才属于新增候选。B 未决定时，更新 A 不应使 B 的待选择提示丢失；仍可手动预览来源选择 C。来源仓库中位于 `.agents/skills/` 下的技能既不作为首次候选，也不作为后来新增（FR-058）。基线如何保存由 T039/T043 落定，不以这个例子要求新增历史系统（FR-011/033/034）。

**预设与 Hermes 都不另建技能内容**：预设保存成员、预设顺序及成员显示顺序，编辑/排序只改组合定义；其部署是叠加、撤销按成员执行。Hermes 使用链路是龙虾库 → default 部署池 → 其他现有档案明确启用，档案选择不是活动档案切换；内容更新不重置启用名单，编辑仍回技能库（FR-023～028）。

**工具资料、安装事实与任务说明分开**：另一机获得工具共享资料不等于安装了工具，软件只检查登记来源，外部 Agent 执行实际维护和核实回写。维护任务中的用户要求、所选技能路径/资料概况/已有部署，或工具简介/本机资料/检查结果/指南，都是执行所需上下文；“引用配套维护 Skill、不内联规范全文”只去掉重复规范，不取消这些上下文，也不启动内置 Agent（FR-044～051）。

**当前范围与开发阶段分开**：Agent 的项目相对路径配置不代表项目技能管理已纳入；内置目录资产和原型模拟不代表当前兼容已验证。M1～M5 是开发检查点，全部实现验收后才投入使用；当前不做的能力不升级为永久禁令（Assumptions、plan.md Milestones）。

## Clarifications

### Session 2026-10-15

- Q: 另一台电脑拉取到指令源变化后，是否刷新本机已有启用目标的 `AGENTS.md`？ → A: 刷新；沿用本机 Agent 启用配置和独立指令路径，按全局在前、专属在后覆盖，不新增分发勾选，也不因拉取自动启用其他目标。
- 用户纠正质检误读：SkillManagerVault 是全项目唯一技能库，各电脑同步同一个库内容；从上游仓库 B 引入的技能存放在 SkillManagerVault，来源、版本检查与更新绑定 B。SkillManagerVault 的跨机同步与技能对上游仓库的检查/更新是两条不同链路，不把另一机拉取 SkillManagerVault 视为重新入库，不存在二选一的来源冲突。
- Q: 工具版本检查的"来源"应该是什么形式？ → A: 来源是一条由 Agent 按工具实际情况编写的检查命令（可查 Git tag、调用接口或查询包管理器）；软件执行命令、解析上游最新版本并与本机安装记录对比，不内置按来源类型的专用解析器。
- Q: 上游检查、库同步、工具版本检查的周期配置是什么关系？ → A: 三项共用一个"自动检查频率"设置（关闭/30 分钟/1 小时/6 小时/24 小时，默认 1 小时）；定时到达时软件自动执行工具的登记检查命令，三类结果的提示分别表达。
- Q: 工具中心的管理操作是否也要求 CLI 可达？ → A: 是。工具中心全部管理操作与技能管理一样 CLI 可达：查看清单与检查状态、单项/全部检查、登记与修改工具资料、回写本机安装记录、生成维护任务。
- Q: GUI 保存自动上传时，工作区还有 Agent 未同意上传的改动怎么办？ → A: 不区分。软件执行上传时提交当前工作区全部改动，不做路径级拆分或改动归属跟踪；Agent 修改后主动询问的维护规范保留（明确同意才上传），但混同上传的后果接受——属少数情况且可改回。
- Q: 配套维护 Skill 怎么组织和入库？ → A: 单一技能（库维护规范、CLI 使用、工具安装登记流程合一），从本项目仓库（用户 GitHub 远端）作为普通上游技能入库与更新，走既有上游检查/更新流程；软件生成的维护任务说明（技能维护任务、工具任务）必须包含该技能在库内的路径与"按其规范执行"的指引，不在任务书内联重复规范全文。

### Session 2026-10-16

- Q: 「本机应用设置」这一整类是否都要 CLI 可达？ → A: 按"是否影响管理动作的结果"分类，不按"是不是设置"分类。共享目录路径按当前用户主目录自动识别且只读，自动检查频率必须 CLI 可写（控制三类自动检查的周期）；全部运行配置与调度事实必须 CLI 可读；主题与字号属界面偏好，不要求 CLI 可写；GUI 保存自动上传的长期授权记录**不得** CLI 可写（Agent 的上传仍需每次取得明确同意）。工具本机安装事实的回写按 FR-047/FR-050 有意只有 CLI 入口，不算缺口。
- 起因：实施核对时只发现共享目录路径一项缺口，逐项清点后确认它是"本机运行配置与只读报告"整类中的一例（同时缺 CLI 的还有自动检查频率、运行配置读取、诊断资料获取与导出、容量报告）。本次按类补齐 FR-050、FR-053 的表述与命令契约，避免同类缺口在后续核对中被反复重新发现。
- 同时清理两处无写入点的配置项：自定义日志目录不再保留（无实际需要，删除即用默认 `<state-dir>/logs`）；Hermes 根改为按 `HERMES_HOME` 环境变量与平台默认解析，不设可写设置键（Hermes 实际位置由该环境变量决定，另设一份可写配置会与之分叉）。

### Session 2026-10-17

- Q: 引入自己的来源仓库时，是否已有声明排除某个技能的能力？ → A: 没有，也不采用仓库内逐项声明排除。问题出在来源发现会把仓库里 `.agents/skills/` 下的技能（例如仓库自带的流程技能）当成可入库候选。
- Q: 正确的排除方式是什么？ → A: 产品主动排除该位置。从来源仓库识别可入库技能时，默认不去找 `.agents/skills/` 里的技能；首次引入与后来新增都适用。这与本机共享部署目录不是同一件事，也不改 FR-033「不入库并记住」的既有语义。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 日常维护自己的技能库 (Priority: P1)

用户打开应用直接进入技能库，通过搜索与筛选找到技能，阅读中文译文理解内容，维护标签、分类、中文注释、支持声明与覆盖层等管理资料；正文与原始文件由外部 Agent 或外部工具修改。龙虾库高频变化：正文、注释、标签、分类与档案分配反复调整，库按持续维护设计，不按一次性整理设计。

**Why this priority**: 掌控感是产品核心目标——看清有哪些技能、做什么、如何组织；六项管理能力在这里共同发挥作用，是区别于单纯下载工具的主要价值。

**Independent Test**: 载入一个已接入的 SkillManagerVault，完成搜索、详情阅读、管理资料修改与分类调整，验证库内目录与部署外的展示随之变化，不依赖入库或部署流程。

**Acceptance Scenarios**:

1. **Given** 技能有中文正文翻译和中文短注释，**When** 用户查看列表与详情，**Then** 原技能名保留，短注释帮助辨认用途，正文默认显示中文并可切换原文；无译文时显示原文。
2. **Given** 技能位于分类 A，**When** 用户将分类改为 B，**Then** 实际目录由 `A/技能名` 移到 `B/技能名`，技能名与部署名不变，分类最多一级，未分类技能在管理域根下。
3. **Given** 分类 A 的技能只拥有标签 X、Y，**When** 用户选择分类 A，**Then** 标签候选只显示 X、Y；选"全部分类"才显示全部标签。该规则同样适用于两个技能库、预设全库浏览与 Hermes 档案。
4. **Given** 用户多选技能批量添加或移除标签，**When** 保存，**Then** 仅目标标签变化，其他标签保持原样；全库标签重命名同时作用于编码库与龙虾库，删除标签只解除关联不删除技能。
5. **Given** 外部工具修改了库内技能内容、管理资料或移动目录，**When** 应用在运行中，**Then** 库内显示自动更新，无需重启。
6. **Given** 同一管理域内已存在同名技能，**When** 创建、入库、收编或复制遇到同名，**Then** 提示并阻止，不覆盖库内原件；编码库与龙虾库之间允许同名。
7. **Given** 技能详情打开，**When** 用户查看文件清单，**Then** 能看到目录层级中的文件与文件夹并可阅读文件，能查看来源地址、来源子目录、采用版本、库内位置与部署位置。
8. **Given** 上游原文已变化而本地译文保留，**When** 用户阅读译文，**Then** 有"译文待更新"提示，译文不被自动清除或覆盖。
9. **Given** 分类 A 下有若干技能，**When** 用户在分类栏重命名为 B 并确认，**Then** 分类目录由 A 改为 B，该分类下全部技能一并移动，技能名与部署名不变；「全部分类」「未分类」没有重命名入口。
10. **Given** 技能库同时有具名分类与未分类技能，**When** 用户查看分类栏，**Then** 顺序为「全部分类」、紧邻的「未分类」、其余具名分类；「未分类」与具名分类的名称左对齐（预留与拖动手柄同宽的空位，但不显示手柄）。
11. **Given** 用户在预设成员浏览或 Hermes 档案技能列表查看分类栏，**When** 新建、重命名或调整具名分类顺序，**Then** 操作与技能库分类栏相同，作用于该管理域的真实分类目录（预设为当前域，Hermes 为龙虾库）；「全部分类」「未分类」仍无重命名入口。
12. **Given** 技能已部署到一个或多个 Agent，**When** 用户归档该技能，**Then** 先从全部受管部署卸载，成功后才把技能目录移入库内归档并在正常列表中隐藏；任一项卸载失败则不归档。还原后保留原分类与标签，不自动重新部署；从归档删除需二次确认。

### User Story 2 - 获得技能进入自己的库 (Priority: P1)

技能经三条途径进入 SkillManagerVault：从来源仓库选择技能入库（可部分入库）；收编本机 Agent 中已有的未受管技能并接管其部署；由 Agent 按规范创建自建技能。进入哪个管理域决定它面向哪类 Agent；创建与首次部署分开。

**Why this priority**: 获得技能是产品主线的起点；没有入库、收编与自建三条途径，后续维护和使用无从开始。

**Independent Test**: 从空库或既有库出发，分别完成一次上游入库、一次收编、一次 Agent 自建技能，验证库内结果与来源记录，不依赖部署流程。

**Acceptance Scenarios**:

1. **Given** 来源仓库包含多个技能，**When** 用户只选择部分技能入库，**Then** 只有选中技能进入指定管理域，保留上游原名，默认分类为仓库名且可修改；即使本次只选一个技能，只要仓库包含多个技能仍按仓库名分类。
2. **Given** 来源仓库只包含一个技能，**When** 用户入库，**Then** 不自动创建仓库名分类，技能进入管理域根下。
3. **Given** 上游技能自带 `.manager` 管理资料，**When** 入库完成，**Then** 标签、译文、注释、支持声明及覆盖层被继承；缺失的资料按默认规则处理（未声明支持范围视为所属管理域内全支持）。
4. **Given** 一次仓库获取已开始，**When** 用户查看或取消，**Then** 能看到真实进度并可取消；较大仓库的获取进度与取消属于必须验证的场景。
5. **Given** Agent 技能列表中存在未受管技能（显示"仅本地"），**When** 用户单项或批量收编并补充中文注释、标签、分类等资料，**Then** 技能进入对应管理域，原 Agent 中的副本接管为受管部署，不需要再部署一次；收编通常针对自建技能，不强制补充上游来源。
6. **Given** 用户让 Agent 创建自建技能，**When** 只要求创建，**Then** 仅在 SkillManagerVault 中创建技能及管理资料，不自动首次部署；明确要求部署时才部署。
7. **Given** 用户将技能复制到另一管理域，**When** 复制完成，**Then** 原技能保留，两份独立维护，副本保留来源记录，不自动部署，两份之间不建立持续同步关系。
8. **Given** 来源仓库在常规目录和 `.agents/skills/` 下都有技能，**When** 用户预览入库，**Then** 候选只包含常规目录中的技能；`.agents/skills/` 下的技能不出现、不入库。

### User Story 3 - 部署技能给本机 Agent 使用 (Priority: P1)

用户将库内技能部署到本机 Agent：单项、多选或按预设，遵守管理域边界与支持声明。部署结果是按目标合成的独立副本：原始文件、按目标 Agent 与当前系统应用的覆盖层、加入的中文注释，不携带 `.manager`。合成只改写注释注入的 `description` 所在行，frontmatter 其余内容（引号样式、行内注释、键与值的类型形态）逐字节保持原样。已有部署随库中内容更新；撤销部署保留库内技能。

**Why this priority**: 部署是技能从资产变为可用的关键动作；部署内容的合成边界与状态表达直接影响用户对结果的掌控。

**Independent Test**: 从已入库技能出发完成单项部署、按预设部署与撤销，核对目标目录的合成内容与 `.manager` 不在场，不依赖上游更新流程。

**Acceptance Scenarios**:

1. **Given** 技能有目标 Agent 专用覆盖层和中文注释，**When** 部署到该 Agent，**Then** 部署内容为原始文件加覆盖层结果加中文注释，库内原始正文未被注释改写，部署目录中不存在 `.manager`；除注释注入的 `description` 行外，frontmatter 其余行与输入逐字节一致（含引号样式与行内注释）。
2. **Given** 技能声明仅支持 Codex，**When** 用户选择部署目标，**Then** 不提供 ZCode 等不支持 Agent 的部署；预设批量部署自动过滤不支持目标。
3. **Given** 当前系统为 Windows，技能仅支持 macOS，**When** 用户查看库，**Then** 该技能整项灰显并禁止部署，原因可读；已保存的支持声明跨重启持续生效。
4. **Given** 技能支持声明收窄，**When** 已有部署或档案启用不再匹配新范围，**Then** 已有部署与启用保留并显示警告，仍可手动禁用；新的部署与启用按声明禁止。
5. **Given** 部署目标存在未受管同名技能，**When** 用户部署，**Then** 直接覆盖并接管为受管部署。
6. **Given** 受管部署副本在 Agent 侧被外部修改，**When** 同步发现本地变更，**Then** 暂停该项覆盖并提示，其余技能正常同步；由 Agent 检查、用户决策，保留的改动整理回 SkillManagerVault 后再同步，管理器不自动替用户选择结果。
7. **Given** 用户在 GUI（图形界面）保存了影响部署内容的修改，**When** 保存完成，**Then** 本机已有部署自动更新；Agent 编辑库文件后调用 CLI（命令行接口）完成同样的部署同步，不依赖 GUI 正在运行。
8. **Given** 技能内容适用于所有读取共享目录的 Agent，**When** 用户部署到共享目录，**Then** 共享目标获得通用内容；需要不同内容的技能分别部署到各自目标。共享目录是部署目标，不是第二个管理库。
9. **Given** 编码库技能需要给龙虾 Agent 使用，**When** 用户尝试直接部署，**Then** 被管理域边界阻止，必须先明确进入龙虾库；支持声明不能绕过管理域边界。
10. **Given** 用户删除库内技能，**When** 确认删除，**Then** 其受管部署一并清理；有本地变更的副本仍先按暂停规则处理。
11. **Given** 技能已有部分 Agent 部署，**When** 用户打开部署界面并调整选择后保存，**Then** 只显示已检测且启用的 Agent，已部署目标亮显；保存仅应用新增与取消选择的差量，未变项不处理；不存在预演选项。
12. **Given** 用户撤销部署，**When** 撤销完成，**Then** 目标副本移除，SkillManagerVault 中技能保留。

### User Story 4 - 吸收上游变化并保留维护成果 (Priority: P1)

用户按来源仓库检查上游变化，查看已有技能的变化文件与新增候选，决定单项更新、仓库批量更新或新增入库；也可以跳过当前版本。所有外部上游（含用户自维护的 Gitea 仓库）都显式更新，检查只展示、不应用。

**Why this priority**: 上游维护是用户明确指出的最重要链路——个人维护成果与上游更新能力共存，更新必须让用户理解变化及其影响。

**Independent Test**: 从一个上游已有新版本的库内技能出发，完成检查、查看变化、单项更新与一次新增候选入库，验证管理资料与分类的保留规则，不依赖跨电脑同步。

**Acceptance Scenarios**:

1. **Given** 已登记来源的技能存在上游变化，**When** 用户执行单项检查或全库检查，**Then** 展示受影响技能及新增、修改、删除的文件，不提供逐行差异界面；检查本身不应用任何变化。
2. **Given** 同一来源仓库在编码库与龙虾库都有技能，**When** 检查更新，**Then** 该仓库只检查一次，结果关联两库相关技能。
3. **Given** 用户选择单个技能更新，**When** 确认，**Then** 仅该技能更新并同步本机已有部署，同仓库其他技能与新增候选不受影响；已采用该版本的技能不重复应用。
4. **Given** 用户选择仓库批量更新，**When** 确认，**Then** 处理该仓库尚未更新的已有技能变化及选定的入库新增；新增入库不自动首次部署。
5. **Given** 更新时上游提供了同项管理资料，**When** 应用更新，**Then** 直接采用上游值，即使本地改过也不进入冲突流程；上游未提供的资料保留本地值；用户维护的分类归属保留。
6. **Given** 来源仓库出现新技能，**When** 用户查看新增候选并选择，**Then** 只有勾选的技能入库；明确"不入库并记住"的决定随库共享，之后不再提示；仅返回列表或未操作不算拒绝。
7. **Given** 某技能当前上游版本不打算采用，**When** 用户跳过该版本，**Then** 常规待更新提示与计数移除，库内技能、资料与部署保留；跳过决定随库共享，可查看、恢复提醒或明确采用；不影响另一管理域副本、其他技能或新增决定；下一版本继续提醒。
8. **Given** 上游变化清单包含删除，**When** 用户确认，**Then** 仅删除技能内文件时移除相应文件、其他变化照常应用，不因此移除整个技能；只有上游删除整个技能时，才移除库内条目并清理受管部署，外改副本仍按暂停规则处理。上游改名按"删除旧技能、新增新技能"处理，不做重命名识别。
9. **Given** 打开软件、点击"检查全部"或到达定时周期，**When** 触发检查，**Then** 上游变化提示更新，应用更新始终需要用户确认。
10. **Given** Agent 需要汇总上游变化，**When** 调用 CLI 全库检查，**Then** 获得两库登记来源的变更汇总，交用户裁决后执行；CLI 与 GUI 遵守相同的更新范围规则。
11. **Given** 已登记来源后来在 `.agents/skills/` 下新增技能，**When** 用户检查新增，**Then** 这些技能不出现在新增候选中。

### User Story 5 - 跨电脑共享维护成果 (Priority: P1)

用户的多台电脑共用一个 SkillManagerVault 远端：技能内容、管理资料、预设、Agent 指令源与工具资料随库同步；部署记录、档案启用名单、指令分发目标与 Agent 本机配置留本机。无冲突的库更新静默拉取并刷新已有部署；上传必须经用户同意——GUI 保存沿用既有自动上传确认，Agent 修改后每次询问。

**Why this priority**: 跨电脑持续维护是核心链路的收尾；上传同意边界与同步范围直接关系用户对自己库的掌控。

**Independent Test**: 用两个独立本机状态模拟两台电脑接入同一 SkillManagerVault：一侧修改并上传，另一侧拉取后验证库内容、已有部署刷新与"新增不首次部署"，不依赖上游更新流程。

**Acceptance Scenarios**:

1. **Given** 本机 GUI 保存了库内修改，**When** 保存完成，**Then** 按既有确认自动提交推送自己的 SkillManagerVault；不提交回来源仓库。
2. **Given** Agent 完成一次库内修改，**When** 修改写入，**Then** Agent 必须主动询问是否上传，得到明确同意才提交推送；CLI 同步部署不构成上传同意。
3. **Given** 工作区存在 Agent 尚未上传的改动，**When** 用户在 GUI 保存或同意 Agent 上传，**Then** 软件提交当前工作区全部改动并推送，不区分改动来源；已同意的上传失败时显示原因，可由用户主动重试上传。后台同步及后台重试不提交或推送，不把用户主动重试已同意上传纳入这一限制。
4. **Given** 远端 SkillManagerVault 有新提交且无冲突，**When** 启动、手动或定时同步触发，**Then** 静默拉取并应用，随后自动更新本机已有部署；库内新增的技能只入库，不自动首次部署。
5. **Given** 拉取发生冲突，**When** 同步暂停并提示，**Then** 由 Agent 检查具体改动、用户裁决后继续，不提供专门冲突合并界面或"保留本地/远端/双方"流程。
6. **Given** 远端不可连接，**When** 用户继续使用本机，**Then** 显示未连接状态，本地库管理、部署与同步已有部署可继续，依赖远端的功能明确不可用；不提供"断开远端"或"重新克隆修复"入口。
7. **Given** 另一台电脑新增了部署，**When** 本机拉取到库变化，**Then** 本机不出现该新增部署；部署记录、档案启用名单、指令分发目标与 Agent 目录配置保持本机状态。
8. **Given** 自动检查周期到达，**When** 触发，**Then** 按共用设置执行上游检查与库同步（关闭/30 分钟/1 小时/6 小时/24 小时，默认 1 小时）；上游变化与库变化的结果分别提示。

### User Story 6 - 通过 Hermes 档案使用龙虾技能 (Priority: P2)

用户按 Hermes 档案管理和使用龙虾技能：技能先进龙虾库并部署到 default 档案，再为其他档案明确启用；所有档案共用库内一份技能内容，档案内只做启用管理。档案独有技能可收编进龙虾库。

**Why this priority**: Hermes 是用户明确的重要使用场景，但依赖龙虾库部署链路（US3）先成立，故列 P2。

**Independent Test**: 从龙虾库已入库技能出发，完成部署 default、为另一档案启用与禁用、批量启停，验证内容唯一与选择保留，不依赖收编流程。

**Acceptance Scenarios**:

1. **Given** 龙虾库技能已部署到 default 档案，**When** 用户为另一档案明确启用，**Then** 该技能进入该档案可用范围；新部署的技能不在其他档案自动启用。
2. **Given** 某档案已启用某技能，**When** 库内该技能内容更新并同步，**Then** 档案使用更新后的同一份内容，档案启用选择不被重置。
3. **Given** 用户在某档案打开技能详情，**When** 查看内容，**Then** 与技能库一致的正文、管理资料与文件展示，但详情只读；修改需前往技能库。
4. **Given** 某档案目录中存在未受管独有技能，**When** 用户收编，**Then** 技能进入龙虾库并同时部署到 default 档案，原档案启用状态保持不变。
5. **Given** 用户在某档案多选技能，**When** 批量启用或禁用，**Then** 一次生效，不依赖预设分配。
6. **Given** 用户期望管理档案本身，**When** 使用产品，**Then** 当前不提供档案创建、删除、改名、活动切换、多实例或 `SOUL.md` 指令管理；软件中的档案选择只用于查看与管理技能。

### User Story 7 - 用预设组合部署与撤销 (Priority: P2)

用户把常用技能组合保存为预设，按组部署和撤销；预设定义随库共享，实际部署由各机决定。

**Why this priority**: 预设提高重复部署效率，但单项与批量部署（US3）已可独立交付价值，故列 P2。

**Independent Test**: 从已有多技能的库出发，创建预设、管理成员、按预设部署与撤销，验证叠加与按成员撤销规则，不依赖上游更新。

**Acceptance Scenarios**:

1. **Given** 预设包含技能 B、C，目标 Agent 已有 A、B，**When** 用户部署该预设，**Then** 结果为 A、B、C——按组增加部署，保留已有其他技能。
2. **Given** 预设包含 B、C，目标 Agent 现有 A、B、C，**When** 用户撤销该预设部署，**Then** 结果为 A——按成员撤销；即使 B 同时属于其他预设也一并撤销，不追踪来源预设或引用计数。
3. **Given** 用户编辑预设成员，**When** 加入或移出技能，**Then** 仅组合定义变化，不自动部署也不自动撤销；只有明确执行部署或撤销才改变目标 Agent。
4. **Given** 用户在另一台电脑打开库，**When** 查看预设，**Then** 组合定义（含顺序与图标）与源机一致；实际部署仍由本机决定。
5. **Given** 用户按预设筛选或查看技能归属，**When** 操作，**Then** 能找到该预设成员与某技能所属的全部预设。
6. **Given** 用户在预设全库浏览中选择分类，**When** 查看标签，**Then** 标签候选遵守分类联动规则（US1 场景 3）。

### User Story 8 - 管理本机 Agent 与指令 (Priority: P2)

用户检测与管理本机 Agent：全量内置 Agent 支持、启停、排序、技能目录与项目技能相对路径配置；Agent 指令源保存在库中，全局加专属拼接后分发到各机决定的目标。每台电脑的软件只管理本机。

**Why this priority**: Agent 目标是部署的前提（US3 依赖其目录配置），但接入配置属于环境准备，故列 P2。

**Independent Test**: 在一台电脑完成检测、启停、目录修改与指令编辑保存，验证目标文件被拼接覆盖，不依赖技能入库。

**Acceptance Scenarios**:

1. **Given** 本机已安装多个内置 Agent，**When** 用户检测或重新检测，**Then** 显示已检测与其他支持 Agent 的分组、启停与排序入口；检测不启动 Agent，也不部署技能。
2. **Given** 某 Agent 使用非默认技能目录，**When** 用户行内修改目录并保存，**Then** 后续部署使用新目录；目录、启用状态与顺序为本机配置，不随库同步。
3. **Given** 用户浏览某 Agent 的本地技能，**When** 查看未受管技能并删除，**Then** 实际文件被删除且不影响 SkillManagerVault；受管技能按撤销部署规则处理。
4. **Given** 用户编辑 Agent 指令，**When** 保存全局内容与某工具专属内容，**Then** 按"全局在前、专属在后"拼接并覆盖对应工具目录的 `AGENTS.md`；没有专属内容时使用全局内容，清空也正常保存。沿用单编辑区、单“保存”按钮，保存后保持打开、切换工具保留未保存草稿，不新增独立分发勾选或保存/分发双按钮。
5. **Given** 指令源内容保存在 SkillManagerVault 中，**When** 另一台电脑拉取库，**Then** 指令源一致，按本机已有启用配置及指令路径自动刷新对应 `AGENTS.md`；不新增启用目标，不改变本机路径，技能路径不被当作指令路径。
6. **Given** 用户想管理远程机器的 Agent，**When** 使用产品，**Then** 不提供直接管理 NAS、VPS 等其他机器 Agent 或远程部署的能力；远端访问仅限 SkillManagerVault 与上游仓库。

### User Story 9 - 用工具中心掌握本机工具 (Priority: P2)

用户通过工具中心掌握缺少可见前端的工具：多台电脑共同维护一份共享工具资料（登记条目、简介、维护指南、版本检查命令），本机安装记录各机独立；软件负责版本检查，外部 Agent 负责实际安装、更新与指南编写；配套 Skill 纳入技能库。

**Why this priority**: 工具中心解决"安装过却遗忘"的真实问题并衔接 Agent 维护流，但独立于技能主链路，故列 P2。

**Independent Test**: 在共享清单已有登记工具的另一台电脑上接入同一 SkillManagerVault，查看"未安装"工具、执行版本检查并复制一个安装任务，不依赖技能部署。

**Acceptance Scenarios**:

1. **Given** 共享清单中某工具在本机未安装，**When** 用户查看工具清单，**Then** 该工具保留在清单中并显示"未安装"（可暗显），不隐藏、不自动提示重装。
2. **Given** 工具已登记版本检查命令，**When** 用户单项或全部检查，**Then** 显示来源、方式、结果与本机安装版本的区别；"未检查""检查失败""未登记命令""可更新"分别表达，不冒充"已是最新"；检查不安装、不升级、不改变本机版本记录。
3. **Given** 用户查看工具详情，**When** 打开概览，**Then** 能读到说明工具是什么、解决哪些问题、用途与适用场景的可阅读简介，以及调用入口、本机安装记录、维护指南入口与配套 Skill 概况，不是只有一句摘要或路径。
4. **Given** 某工具需要安装或更新，**When** 用户生成维护任务并交给外部 Agent，**Then** 任务带上用户要求、简介、本机安装资料、检查结果、维护指南，以及配套维护 Skill 在库内的路径与"按其规范执行"的指引；生成任务不代表已开始或已完成。Agent 完成操作后读取真实版本、验证并回写；失败如实报告，不能只改版本字段冒充完成。
5. **Given** 工具缺少维护指南，**When** Agent 安装或补写，**Then** 指南说明用途与调用入口、实际安装方式、安装与配置位置、版本检查命令、更新步骤、验证方式及注意事项，可随工具实际情况持续维护。
6. **Given** 工具有配套 Skill 候选，**When** 用户入库，**Then** 同页展示来源与具体候选（原名、中文注释、用途、勾选状态、已选数量；单个候选也列出），选择后补充分类、注释、标签入库，沿用技能库全部规则；入库不自动部署；工具版本与配套 Skill 版本分别管理。
7. **Given** 本机安装了清单之外的工具，**When** 用户想登记，**Then** 由用户让 Agent 检查并登记（含编写指南、写入共享资料并回写本机记录）；软件不扫描路径、包管理器或其他位置做自动发现。
8. **Given** 用户登记或修改了工具资料，**When** 写入 SkillManagerVault，**Then** 属于库修改，沿用"Agent 修改后询问、明确同意才上传"约定；工具程序本身不在同步范围，实际安装各机独立完成。

### User Story 10 - 界面环境与可维护性 (Priority: P3)

用户获得稳定的桌面使用环境：主题与字号、托盘后台、故障诊断信息与容量报告。

**Why this priority**: 提升日常使用体验与问题排查效率，但不阻塞核心链路，故列 P3。

**Independent Test**: 调整主题与字号、关闭窗口、从托盘操作并导出诊断信息，验证行为符合下述场景，不依赖任何技能数据。

**Acceptance Scenarios**:

1. **Given** 系统切换深浅色，**When** 应用主题为"跟随系统"（默认），**Then** 界面随之切换；用户可固定浅色或深色，可调整文字大小。
2. **Given** 用户点击窗口关闭，**When** 关闭完成，**Then** 应用收起到系统托盘继续后台运行，既定定时检查与同步继续执行；仅托盘菜单"退出"才真正退出，托盘提供重新打开窗口与检查上游更新的入口。
3. **Given** 下载失败或部署异常发生，**When** 用户需要排查，**Then** 可获取崩溃记录、诊断信息与日志交给 Agent。
4. **Given** 用户查看容量报告，**When** 打开，**Then** 能看到技能库占用空间与体积较大的技能。
5. **Given** 新电脑已安装桌面应用与配套维护 Skill，且未配置命令搜索路径，**When** 外部 Agent 按技能说明定位应用内 CLI 并执行管理命令，**Then** 使用安装包随附的同版本 CLI，无需源码、Rust 工具链或另行安装 CLI，且 GUI 未运行时仍可使用。
6. **Given** GitHub 公开更新源有更高 SemVer（语义化版本），**When** 应用启动完成，**Then** 提示新版本与说明，经用户确认后下载、验签、安装并重启；检查失败或已是最新不打断使用。设置页可查看当前版本并再次检查。

### Edge Cases

- **同库同名**：创建、入库、收编、复制遇同一管理域同名时提示并阻止；两管理域允许同名（见 US1 场景 6）。
- **支持范围收窄**：已有部署与档案启用保留并警告，不自动撤销；新部署禁止（US3 场景 4）。
- **受管副本本地变更**：暂停该项、其余继续，交 Agent 检查、用户决策（US3 场景 6）。
- **上游改名**：按删除加新增处理，无自动改名识别（US4 场景 8）。
- **上游删除**：经用户确认移除库内技能并清理受管部署；有本地变更的副本先按暂停规则处理（US4 场景 8、US3 场景 10）。
- **库同步冲突**：暂停本次同步，交 Agent 与用户，无专门冲突界面（US5 场景 5）。
- **远端不可用**：显示未连接，本地管理与部署继续（US5 场景 6）。
- **覆盖层整份替换**：操作者设置整份 `SKILL.md` 替换后，上游新正文不自动进入替换结果，由操作者承担；不加自动合并或强制复核。
- **上游仅管理资料变化**：上游提供同项管理资料时采用上游值并推进版本，本地改过同项也不进冲突流程（US4 场景 5）。
- **空值与缺资料**：无译文显示原文；未声明支持范围按所属管理域内全支持；未登记检查命令的工具如实显示"未登记命令"。
- **批量部分完成**：不适用、同名受阻、失败与副本暂停均按条目表达，明确成功项与未处理原因，其余可处理项继续；不要求整批回滚。同名阻止针对库内待写入条目，不改变未受管目标同名直接接管的规则。
- **获取失败或取消**：仓库获取阶段不写入技能库，失败/取消不报告入库成功；可保留可复用的获取缓存，不承诺清除所有临时字节。后续逐项入库若部分失败，明确报告已完成条目与失败条目，不引入整批事务或自动回滚。
- **来源中的 `.agents/skills/`**：从来源仓库识别可入库技能时，该路径下的技能默认不是候选；首次引入与后来新增都跳过。本机共享部署目录仍按既有规则浏览与部署，不受这条发现规则影响。
- **译文时效**：原文正文变化而本次未维护译文时保留译文并提示待更新；用户或 Agent 按当前原文补写并保存译文后解除提示。本次采用的上游若同时提供对应新原文的译文，则采用并视为本次译文更新；不审查翻译质量，不增加翻译历史。

## Requirements *(mandatory)*

### Functional Requirements

**技能库与组织**

- **FR-001**: 系统必须直接管理用户指定的本地 SkillManagerVault 根目录，其中编码技能库（`code/`）与龙虾技能库（`lobster/`）分别管理，由 SkillManagerVault 自身的 Git（版本管理）仓库统一跟踪；不另存第二套中央技能内容。
- **FR-002**: 首次接入必须选择已存在的本地 SkillManagerVault 仓库（含已配置远端），不提供克隆或创建向导；仓库操作复用本机 Git 及其已有认证配置，不提供独立登录授权。
- **FR-003**: 分类必须是实际文件夹（最多一级），未分类技能位于管理域根下；修改单个技能分类或重命名分类目录，都必须移动实际目录且不改变技能名与部署名。「全部分类」「未分类」不可重命名。分类栏顺序必须是「全部分类」、紧邻的「未分类」（仅当存在未分类技能时显示）、其余具名分类。「未分类」与具名分类的名称左对齐，预留与拖动手柄同宽的空位，但不显示手柄、不可拖动。凡展示分类栏的模块（技能库、预设成员浏览、Hermes 档案，以及今后新增的同类界面）都必须提供与技能库相同的分类新建、重命名与排序入口，复用同一套分类管理能力。
- **FR-004**: 同一管理域内必须禁止同名技能（创建、入库、收编、复制时提示并阻止）；两管理域之间允许同名。

**管理资料（Manager layer）**

- **FR-005**: 每个技能的管理资料必须保存在其 `.manager` 中，包含多个标签、中文短注释、中文正文翻译、Agent 与 OS 支持声明、overlay（覆盖层）；资料随技能目录移动，可由 GUI 或 Agent 反复维护。
- **FR-006**: 中文注释必须仅在部署时加入 Agent 使用的技能内容，不回写库内原始正文；中文译文仅用于管理器阅读，不作为部署正文；上游原文变化后译文保留并提示待更新。
- **FR-007**: 未声明支持范围必须视为所属管理域内全支持；显式空支持集合表示该维度不支持任何目标，不与未声明混同。Agent 不适用时禁止新增部署及档案启用并在批量操作中过滤；当前系统不适用时技能整项灰显、禁止新增部署及启用，并在库列表中按原相对顺序排到受支持技能之后，保持可见、可阅读与可维护，不隐藏也不改其他排序；支持收窄不自动撤销已有部署与档案启用，保留并警告，仍允许库内维护和手动撤销/禁用。
- **FR-008**: 覆盖层必须同时适用于自建与有上游的技能，支持按目标 Agent 与系统替换原技能文件（含整份 `SKILL.md`）；替换后的效果由操作者承担，不做自动合并或强制复核。
- **FR-009**: 系统必须支持按名称、描述、中文注释、来源、分类、标签组合筛选与搜索，支持筛出无标签技能、部署到指定 Agent 的技能及按预设筛选；全库标签可统一重命名（两库生效）与删除（仅解除关联）。
- **FR-010**: 技能详情必须展示中英文正文切换（有译文默认中文）、来源地址与所选分支/引用（未指定时为远端默认分支）、子目录、采用版本、库内位置、部署位置及带目录层级的文件清单；正文按 Markdown 结构化阅读视图渲染（标题、段落、列表、引用、链接、行内代码和代码块），代码块跟随当前主题；正文滚动时页签与阅读状态控件保持可见。库内位置在「文件与部署」和详情页脚呈现，来源页不重复展示。保留已确认的列表/网格切换，技能以原名识别，不新增独立中文名称或中文简介字段。

**技能获取**

- **FR-011**: 系统必须支持从来源仓库选择技能部分入库：保留上游原名，多技能仓库默认按仓库名分类（GUI 可改、CLI 经对话确认名称后传入），单技能仓库不自动分类；不做技能依赖解析或自动补齐。可入库候选的发现范围见 FR-058。
- **FR-012**: 入库必须继承上游自带 `.manager` 资料，缺失项按默认规则处理；系统必须登记来源仓库、上游路径与采用版本用于后续仓库级更新检查。
- **FR-013**: 仓库获取必须呈现真实可见进度并允许取消；展示真实获取阶段及可得的进展量，不以循环动画或虚构百分比代替进度，未知总量可如实说明。取消意味着停止本次获取、后续不继续该获取且不误报已入库，缓存残留按边界说明处理；较大仓库获取属于必须验证的场景。
- **FR-014**: 系统必须支持从本机 Agent 与共享目录列表单项或批量收编未受管技能进入对应管理域，接管原有部署，并支持补充中文注释、标签、分类、支持声明与译文；共享目录收编进入编码库并接管原共享目标，不新增其他目标部署。卡片入口仅显示收编图标，悬停与无障碍名称说明「纳入管理」；收编不强制补充上游来源。
- **FR-015**: Agent 必须能按规范在 SkillManagerVault 中创建自建技能；创建与首次部署必须是两个独立动作，均按用户命令执行。
- **FR-058**: 从来源仓库识别可入库技能时，系统必须默认不去找 `.agents/skills/` 里的技能。该路径下的技能不进入首次引入候选，也不进入后来新增候选；不要求用户逐项声明排除，也不把这条规则做成仓库内的排除清单。本机共享部署目录（当前用户主目录下的 `.agents/skills`）仍按 FR-021/FR-042/FR-055 作为部署与浏览目标，不受本条影响。

**部署与撤销**

- **FR-016**: 部署必须是合成后的独立副本：原始文件、按目标 Agent 与当前系统应用的覆盖层、中文注释；不携带 `.manager`。中文注释只注入入口文件 frontmatter 的 `description`；合成不得改变其余 frontmatter 内容的形态（引号、行内注释、键与值的类型），防止字符串被 YAML 隐式类型改写。
- **FR-017**: 部署必须遵守管理域边界（编码库技能不得直接部署给龙虾 Agent）与支持声明过滤；两规则互相不可绕过。
- **FR-018**: 未受管同名目标必须直接覆盖并接管为受管部署，不做同名冲突检查。
- **FR-019**: 库内部署内容变化必须更新本机已有部署：GUI 保存自动触发；Agent 编辑库文件后必须调用 CLI 完成同步，不依赖 GUI 运行。
- **FR-020**: 受管部署副本出现外部本地变更时，系统必须暂停该项并提示，其余继续同步；处理由 Agent 检查、用户决策；不提供专用差异查看或冲突合并界面。
- **FR-021**: 系统必须支持单项、多选与批量撤销部署（撤销保留库内技能）、批量部署；GUI 与 CLI 均支持一次选择多个技能及多个指定 Agent，逐个技能/目标遵守准入与结果规则，不限于多技能单目标。编码域技能可部署到自动识别的 `<当前用户主目录>/.agents/skills`（作为部署目标而非第二管理库，无需设置或自定义路径；浏览不创建目录，首次部署时创建）；共享部署要求所有消费者均受支持且能使用相同内容，不因存在 overlay 目录机械拒绝。管理器按编码 Agent 均读取共享目录的既有产品假设处理，不增加逐 Agent 读取声明，也不将该假设冒充实际兼容验证。GUI 部署界面显示本管理域已检测且启用的 Agent；编码库的单项、多选及预设部署同时显示「共享 Agent」，即使没有已检测的 Agent 也可选择该共享目标，部署到自动识别的共享目录。各目标按真实部署状态亮显；点击切换选择，点击「保存」按变化项分别部署或撤销。多技能部分已部署时标示数量，未经选择保持原状态。技能卡片右下角显示快捷部署图标并保持紧凑右对齐；编码库卡片同时包含共享 Agent 目标，点击立即部署或撤销，成功后刷新亮暗；悬浮提示立即显示目标名，不附加动作词。技能详情「文件与部署」直接以带图标的目标项表达已有部署并支持点击部署/撤销，只显示目标名，不再使用「本机已有部署」标题；该页签页脚不重复显示部署按钮。未受管技能须先收编。取消 GUI、CLI 与底层预演功能；CLI 保留直接部署和撤销命令，以及显式共享目录/Hermes default 目标。
- **FR-022**: 删除库内技能必须一并清理其受管部署；存在本地变更的副本仍先按暂停规则处理。库内条目可移除，暂停副本与其实际路径/处置记录必须保留，报告“库已删除、该副本清理暂停”，不冒充已全部清理；由 Agent 检查并按用户裁决继续清理。

**预设**

- **FR-023**: 预设必须按管理域组织，成员来自对应库，同一技能可属多个预设；组合定义（含排序与图标）随 SkillManagerVault 同步，部署状态由各机维护。
- **FR-024**: 预设部署必须按组叠加（保留目标已有其他技能）；撤销必须按成员批量执行且不追踪来源预设或引用计数；编辑成员不得改变实际部署。
- **FR-025**: 系统必须支持预设的新建、重命名、图标选择、预设显示顺序及其成员显示顺序调整，并支持筛选查看技能归属；两种排序都不改变分类目录、成员集合或实际部署。GUI 的「预设」入口位于「工具中心」下方并与其同级，不设「编码预设 → 全部预设」分组；进入后直接显示页内预设列表与当前预设的成员浏览，不提供预设卡片总览。初次进入或切换管理域时默认选择该域首项；删除当前项后选择剩余首项；无预设时仍保留管理域切换与新建入口。

**Hermes 档案**

- **FR-026**: 系统必须按一个 Hermes 根目录下的多个档案管理：技能先部署到 default 档案，再由用户明确为其他档案启用；新增不自动启用；档案共用库内一份技能内容。档案选择显示 Hermes 配置的 bot 显示名（优先 `profile.yaml` 的 `ui_meta.hermes-bots.title`，回退 `SOUL.md` 标题，再回退目录 id），不直接以内部档案 id 作为界面名称。
- **FR-027**: 档案技能详情必须只读（与技能库一致的展示），修改前往技能库；各档案启用名单为本机状态，内容更新不得重置启用选择。
- **FR-028**: 档案独有技能必须可收编进龙虾库并部署到 default 档案，原档案启用状态保持；档案内支持普通批量启停；不做档案创建、删除、改名、活动切换、多实例与 `SOUL.md` 管理。

**上游更新**

- **FR-029**: 系统必须支持启动时、手动与定时检查上游；定时周期由共用的"自动检查频率"设置控制（关闭/30 分钟/1 小时/6 小时/24 小时，默认 1 小时），上游检查、库同步（FR-037）与工具版本检查（FR-046）三项共用该设置。手动触发必须同时可由 GUI 与 CLI 表达：GUI 以一次统一调度执行三项，CLI 由上游检查、库拉取、工具检查各自的命令分别表达，不新增组合命令。检查只展示变化（新增、修改、删除文件），不应用；所有外部上游（含自维护 Gitea）一律经用户确认更新。
- **FR-030**: 来源检查必须按仓库进行，同一仓库跨两管理域只检查一次；单技能采用版本分别记录，同一版本不重复应用。
- **FR-031**: 系统必须同时支持单技能更新（仅影响所选条目）与仓库批量更新（处理待更新条目及选定新增）；GUI 与 CLI 遵守相同范围；更新前展示变化。
- **FR-032**: 更新必须保留用户维护的分类；上游提供同项管理资料时采用上游值（本地改过同项也不进冲突流程），上游未提供则保留本地资料。
- **FR-033**: 上游新增候选必须由用户勾选入库（即使单个候选也列出具体名称与资料）；"不入库并记住"的决定随库共享且不再提示；返回列表或未操作不算拒绝。新增候选的发现范围同样遵守 FR-058。
- **FR-034**: 系统必须支持跳过单技能当前上游版本（含删除类变化）：提示移除、决定随库共享、可查看、恢复提醒或明确采用，不影响其他条目；仓库批量更新必须尊重跳过决定。
- **FR-035**: 上游改名必须按删除加新增处理；上游删除整个技能经确认后移除库内条目并清理受管部署。技能内部文件的删除属于该技能内容更新，不因此删除整个技能。

**SkillManagerVault 跨电脑同步**

- **FR-036**: 同步范围必须是：技能内容、`.manager` 管理资料、预设定义、Agent 指令源、工具共享资料随库共享；部署记录、Hermes 档案启用名单、指令分发目标、Agent 本机配置留本机（见 ADR 0001）。
- **FR-037**: 库拉取必须支持启动、手动与定时；定时执行共用 FR-029 的"自动检查频率"设置。无冲突时静默应用并自动更新本机已有部署；库内新增不自动首次部署。GUI 全局页头在「Agent 指令」入口左侧提供更新图标，所有页面均可直接检查并拉取当前 SkillManagerVault；拉取期间图标旋转并禁止重复点击，其余页面操作保持可用，结束后刷新当前页面并显示实际结果或错误。此入口只拉取自己的库，不检查技能上游或触发上传。
- **FR-038**: 上传边界：仅两条路径执行提交推送——本机 GUI 保存沿用既有自动上传确认，Agent 修改后经询问获得明确同意再执行上传；CLI 同步部署不构成上传同意。软件执行上传时提交当前工作区全部改动，不区分改动来源；不向来源仓库提交。GUI 本地保存完成后，已有部署刷新与获授权的上传在后台继续，不能等待网络完成才结束保存；上传、拉取及同步状态检查期间仍可切换页面、浏览与编辑本地资料，完成或失败时如实提示，失败不自动重试。后台执行方式不构成新的上传授权路径。
- **FR-039**: 库同步冲突必须暂停并提示，由 Agent 检查、用户裁决后继续；不提供冲突合并界面或历史版本查看恢复功能。
- **FR-040**: 远端不可用时必须显示状态且本地管理、部署可继续；不提供断开远端或重新克隆修复入口。

**Agent 接入与指令**

- **FR-041**: 系统必须保留全量内置 Agent 名单与本机检测、重新检测、启停、排序及技能目录行内修改；检测不启动 Agent、不部署技能；目录与启停为本机配置。**这些入口位于设置页**（与原型及 001 规格 FR-031 一致）：设置页首个区块为「支持的 Agent（已检测数/内置总数）」，含已检测/已启用摘要、全部启用／全部禁用／重新检测、已检测 Agent 卡片网格（拖动排序、启停、技能目录与项目相对路径行内修改、恢复默认）以及「其他支持的 Agent」折叠区。
- **FR-042**: 系统必须支持浏览**本机目标**（内置 Agent 目录、共享目录与 Hermes default 档案）的技能并直接删除未受管项（单项与多选）；受管项按撤销部署规则处理。共享目录自动定位为 `<当前用户主目录>/.agents/skills`。本机 Agent 与共享目录列表无技能或筛选无结果时留白，不显示空状态提示或底部解释。卡片可点击只读查看本机实际副本的正文及文件，不以库内原件代替；受管技能可从详情前往技能库管理。
- **FR-043**: Agent 指令源必须保存在 SkillManagerVault 中并随库同步；编辑支持全局与逐 Agent 专属内容，保存时按"全局在前、专属在后"拼接覆盖对应工具的 `AGENTS.md`；无专属使用全局内容，空内容正常保存。保留单编辑区与单保存按钮，不另设分发勾选或保存/分发双按钮；向哪些 Agent 分发沿用各机的 Agent 启用配置及独立指令目标路径，不将技能路径当作指令路径。SkillManagerVault 拉取到指令源变化后，按同一拼接覆盖规则刷新本机已有启用目标，不改变本机启用名单或指令路径。指令管理与 Hermes 档案指令互不扩展。
- **FR-055**: 系统必须在编码域提供共享目录的固定入口与技能浏览页，与本机 Agent 技能浏览同构（受管／仅本地／本地有变更的区分与筛选、只读查看本机详情、收编未受管项、删除未受管项、打开库内对应技能）；共享目录始终是本机部署目标，本能力不使它成为可登记的自定义 Agent 或第二个管理库；路径按 FR-021 自动识别，不提供前往设置或修改路径的入口。CLI 以 `agent local-skills/read-local/delete-local <target>` 提供浏览、阅读与删除，`<target>` 接受内置 Agent key、`shared` 或 `hermes:default`；`skill adopt <target>` 收编接受内置 Agent key 或 `shared`。
- **FR-056**: 设置页必须按原型分组呈现，区块顺序为「支持的 Agent」（见 FR-041）→「全局配置」→「自己的 SkillManagerVault 同步」→「后台检查与上游更新」→「诊断与日志」。全局配置行至少包含：SkillManagerVault 目录（当前路径）、技能归档（「查看归档」打开归档管理，见 FR-060）、共享技能目录（自动识别当前用户主目录下的 `.agents/skills`，只读）、部署方式（只读展示当前唯一实现——文件复制）、主题、文字大小、语言（只读展示"简体中文"）、关闭行为（只读展示"托盘模式"）、软件版本（当前 SemVer，可手动检查应用更新）。后台检查区块含检查频率与立即检查（复用既有检查与同步能力，不新增组合命令）。后续里程碑新增的配置（自动上传确认、技能库容量、诊断与运行日志）保留在本页，不因对齐原型而删除。
- **FR-057**: 编码 Agent 分组的「全部 Agents」页必须是**跨目标部署清单**（原型语义）：列出本机各部署目标上的技能，区分受管／未受管／本地有变更，提供搜索、筛选与刷新，并可发起从库部署；不得再把它用作 Agent 检测或启停入口（那些在设置页，见 FR-041）。

**工具中心**

- **FR-044**: 工具登记条目、简介、维护指南与版本检查命令必须作为共享资料随 SkillManagerVault 同步；本机安装记录（版本、安装方式、安装与配置位置、检查状态）各机独立；工具程序不在同步范围。
- **FR-045**: 工具清单必须展示名称、用途、能力标签、本机版本、检查状态、维护指南与配套 Skill 状态，支持搜索、一级分类与状态筛选；本机未安装的工具保留显示"未安装"（可暗显），不隐藏、不自动提示重装。
- **FR-046**: 软件必须负责版本检查（单项与全部）：全部检查支持手动执行并按 FR-029 共用周期定时执行登记的检查命令；依据该工具登记的检查命令（由 Agent 编写）执行并解析上游最新版本，与本机安装记录对比，展示来源、方式与结果，区分未检查、检查失败、未登记命令与可更新；软件不为特定来源类型（Git 仓库、包管理器等）内置专用检查逻辑。检查可保存本机检查结果，不安装、不更新、不改变本机安装事实；未安装工具的成功检查只表示已获知上游版本，不表示已安装或已是最新。
- **FR-047**: 实际安装、更新与指南编写必须交给外部 Agent：系统生成可复制的维护任务（带用户要求、简介、本机资料、检查结果与指南）；Agent 完成后核实真实版本并回写，失败如实报告；工具登记与资料维护由 Agent 完成，软件不做自动发现。
- **FR-048**: 维护指南必须至少说明用途与调用入口、实际安装方式、安装与配置位置、版本检查命令、更新步骤、验证方式与注意事项，按工具实际持续维护。
- **FR-049**: 配套 Skill 必须经用户勾选入库并沿用技能库全部规则（来源、管理层、上游更新、部署）；入库页必须列出具体候选及资料（单个候选也列出）；工具版本与 Skill 版本分别管理。

**入口、界面与环境**

- **FR-050**: 全部核心管理操作必须同时可通过 GUI 与 CLI 完成，包括技能侧（入库、收编、检查与更新、部署同步、预设、标签、分类、注释、译文/覆盖层、支持范围、Hermes 管理、归档/还原/从归档删除）、工具中心侧（查看工具清单与检查状态、单项/全部检查、登记与修改工具资料、回写本机安装记录、生成维护任务）与本机运行侧（读取运行配置与调度事实（含自动识别的共享目录）、设置自动检查频率、获取与导出诊断资料、查看库容量报告）；CLI 以 Agent 调用为主要场景；不要求用户回 GUI 补裁决。遵守 FR-047 的工具登记、资料维护和安装结果回写由外部 Agent 经 CLI 完成，GUI 提供生成/复制对应任务的入口，不内置执行 Agent，也不以直接修改版本字段代替真实核实。
  - **安装交付**：桌面安装包必须随附同版本 CLI，维护 Skill 必须说明安装后的定位与调用方式；不以开发目录里的可执行文件作为发行入口。外部 Agent 无需依赖 `PATH`（命令搜索路径）、源码或编译工具链即可调用，且不要求 GUI 正在运行。只有技能文件不等于已安装 CLI；文件缺失或执行失败须如实说明。

  本机运行侧的双入口边界（2026-10-16 补充，按"是否影响管理动作的结果"划分）：

  - **必须 CLI 可写**：自动检查频率，控制 FR-029 三项自动检查的周期，需可由 Agent 按用户指令调整。共享目录按 FR-021 自动识别，GUI 与 CLI 均只读展示，不保存可写路径。
  - **必须 CLI 可读**：全部本机运行配置与调度事实，含只由 GUI 写入的主题、字号与上传授权记录，使 Agent 能解释当前行为（例如为何未自动检查）。
  - **不要求 CLI 可写**：主题与字号属界面偏好，不影响技能、部署、同步或检查结果（见 FR-052）。
  - **不得 CLI 可写**：GUI 保存自动上传的长期授权记录（FR-038）。该授权由用户在 GUI 给出，Agent 不得自行开启；Agent 的上传路径仍是每次取得明确同意后显式调用。
  - **有意为单侧**：工具本机安装事实的回写只有 CLI 入口、GUI 不提供（见 FR-047 与上文），不构成缺口。
- **FR-051**: 配套维护 Skill 是 SkillManagerVault 中的普通技能，随软件开发同步更新：技能源文件维护在本项目仓库中，本项目推送到用户远端（GitHub）后，该技能从本仓库作为普通上游技能入库（登记来源记录），后续更新走既有上游检查与更新流程，不新增专用分发、升级或冲突机制。技能为单一技能，内容涵盖库维护规范（`.manager` 格式、目录与同名规则、译文与注释边界、修改后同步部署与询问上传、冲突处理）、CLI 使用参考、工具安装与登记流程。软件生成的维护任务说明必须包含该技能在库内的路径及"按其规范执行"指引，不重复规范全文；技能任务支持单项或多选，保留用户要求、本机 SkillManagerVault 路径、所选技能库内路径、注释/分类/标签/支持声明、译文/覆盖层概况及本机已有部署，不把完整仓库内容塞入任务。工具任务保留 FR-047 的上下文，不因引用维护 Skill 而删掉必要事实；不引入内置 Agent 或任务队列。
- **FR-052**: 应用必须提供浅色、深色与跟随系统主题（默认跟随系统）、文字大小调整；正常关窗收托盘后台运行，托盘"退出"才终止，托盘提供重开窗口与检查上游更新入口。托盘图标左键点击在显示与隐藏主窗口之间切换，显示时取消最小化；菜单由右键展开，仍是"重新打开窗口／检查上游更新／退出"的入口。主题与字号属界面偏好，不属于 FR-050 要求的双入口范围（CLI 只读得到当前取值，不提供写入）。 界面不常驻展示内部实现、重复操作说明或规则注释；保留字段名、状态、真实错误、破坏性操作影响与必要确认。

  可用的按钮、侧栏导航、可点击卡片、文件入口及选择控件在鼠标悬停时必须显示手型光标；禁用控件不显示可点击手型。
- **FR-053**: 应用必须提供可获取的崩溃记录、诊断信息与日志用于 Agent 排查，以及技能库容量报告（占用与较大技能）；两者均必须同时可由 GUI 与 CLI 获取，诊断导出返回真实文件路径。排查资料包含版本、平台、有关路径、操作/错误与发生时间，由用户主动获取；不记录认证凭据或令牌，不自动上传诊断资料。
- **FR-054**: 界面语言仅提供简体中文；不做旧版数据兼容与迁移。
- **FR-059**: 桌面应用必须在启动后检查 GitHub 公开更新源是否有更高 SemVer 版本；发现更新后提示版本与说明，经用户确认才下载、验签、安装并重启。检查失败或已是最新不得打断使用。设置页「全局配置」展示当前版本并提供手动检查；用户关闭更新提示后，应用左下角必须常驻「发现新版本 + 立即更新」入口，直到安装完成或退出，不得只靠一次弹窗。更新源为公开仓库 `YYFF925/SkillManager` 的 HTTPS 静态清单（`updater-manifests`）与 GitHub Releases 产物，使用 Tauri updater 验签；不得把令牌写进应用。仓库不接 Issue / Pull Request。macOS（当前交付 Apple Silicon）与 Windows（x64 NSIS）都必须能检查并安装各自平台的更新，两平台可错开发布。本能力不属于技能管理双入口，不要求 CLI。尚未含 updater 的旧安装包不能被远程升级，需手动安装一次含 updater 的版本。版本号为 SemVer `MAJOR.MINOR.PATCH`：每次发布应用更新升 PATCH；MINOR 不自动升；MAJOR 仅用户明确要求大更新时升。
- **FR-060**: 系统必须支持将暂时不用的技能归档到 SkillManagerVault 的 `archive/<domain>/[<category>/]<name>/`，完整保留技能文件与 `.manager`（含原分类目录层级、标签等）。归档后技能不得出现在正常技能库列表中。若该技能已有受管部署，归档必须先从全部已安装 Agent 卸载；任一项卸载失败则不得移入归档，避免出现已归档但仍安装的状态。设置页提供「查看归档」；归档管理可还原与删除。还原后技能回到正常库并保留原分类与标签，不自动重新部署。从归档删除须二次确认。GUI 与 CLI 均可完成归档、列出、还原与删除。

### Key Entities *(include if feature involves data)*

- **SkillManagerVault**: 用户自己的 Git 仓库与唯一技能内容源，含编码/龙虾两管理域、预设、指令源与工具共享资料；有远端，跨电脑同步。
- **管理域（Management domain）**: 编码（`code/`）与龙虾（`lobster/`）两个技能库，决定技能面向的 Agent 类别与部署边界。
- **技能（Skill）**: 独立维护与部署的能力单元，由原始内容与 `.manager` 管理层组成；上游技能保留原名与来源记录，自建技能由 Agent 按规范创建。
- **管理层（`.manager`）**: 标签、中文注释、中文正文翻译、支持声明、覆盖层；随技能目录移动，不进入部署结果；上游同项值优先。
- **来源记录（Source record）**: 技能入库时登记的仓库、上游路径与采用版本，支撑仓库级检查与更新。
- **部署（Deployment）**: 面向本机 Agent 目标（含共享目录与 Hermes default 档案）的合成副本；部署记录为本机状态。
- **预设（Preset）**: 按管理域组织的可复用技能组合，定义随库共享；部署叠加、撤销按成员。
- **Hermes 档案（Hermes profile）**: 单根目录下的独立配置与数据目录；共用库内一份技能，启用名单本机维护。
- **Agent 目标（Agent target）**: 内置名单中的本机编码/龙虾 Agent，含本机目录配置、启用状态与顺序；共享目录为特殊部署目标。
- **指令源（Instruction source）**: 保存在库中的全局与逐 Agent 专属指令内容，分发覆盖目标工具的 `AGENTS.md`，分发目标本机决定。
- **工具登记（Tool record）**: 工具中心的共享资料（条目、简介、指南、版本检查命令）与本机安装记录的组合；配套 Skill 是库内普通技能。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 核心业务旅程完整可交付——在一个真实 SkillManagerVault 上依次完成"上游入库 → 管理资料维护 → 部署给本机 Agent → 吸收一次上游更新 → 上传并在第二台电脑拉取后继续使用"，每步结果可对照本规格验收场景核实。
- **SC-002**: 全部核心管理操作清单逐项核对均有 CLI 路径可达（对照 FR-050 操作清单验收），Agent 无需回 GUI 补做任何核心操作。
- **SC-003**: 部署内容边界百分之百成立——抽查任意部署结果均不含 `.manager`、中文注释未回写库内原件、阅读译文未进入部署正文（对照 FR-006/FR-016 验收）。
- **SC-004**: 状态表达诚实——"未检查、检查失败、未登记命令、待更新、任务已生成"在任何界面与 CLI 输出中均不冒充"最新、已安装、已更新、已完成"（对照宪章原则 I 与 US4/US9 场景验收）。
- **SC-005**: 上传路径可验证——仅 GUI 保存的既有自动上传与 Agent 获同意后的上传两条路径会执行提交推送；后台路径不提交或推送，已获同意的上传失败可由用户主动重试上传（对照 FR-038 验收）。
- **SC-006**: 跨电脑边界可验证——第二台电脑拉取后，库内容、预设、指令源与工具清单一致，且不出现自动首次部署、自动档案启用或自动工具安装（对照 FR-036/FR-037 验收）。
- **SC-007**: 上游更新保留规则可验证——完成一次包含管理资料与删除变化的更新后，用户分类保留、上游未提供的资料未丢失、明确拒绝的新增不再提示（对照 FR-032/FR-033 验收）。
- **SC-008**: 较大仓库获取场景通过实际验证，进度可见且取消生效（对照 FR-013 验收）。
- **SC-009**: 来源发现跳过 `.agents/skills/` 可验证——预览一个同时含常规技能与该路径下技能的来源时，候选不含后者；该来源后来只在该路径下新增技能时，新增提示也不出现这些技能（对照 FR-058 验收）。
- **SC-010**: 已安装含 updater 的版本后，发布更高 patch 时启动能提示并可完成安装重启；设置页显示当前版本（对照 FR-059 验收）。
- **SC-011**: 技能归档边界可验证——归档后正常列表不含该项、归档目录保留分类与标签；已部署技能归档后副本已卸载且部署记录清空；任一项卸载失败则库内条目仍在原处；还原后不自动重新部署（对照 FR-060、US1-12 验收）。

## Assumptions

- 用户已具备本地 SkillManagerVault Git 仓库及其远端，Git 认证（SSH 或已存凭据）已在本机配置；首次接入以选择已有本地库的方式进行。
- 首版不内置 Agent：实际安装、更新、翻译、指南编写等执行性工作由外部 Agent 承担；软件负责库管理、状态展示与版本检查。
- 首版范围排除（均为当前范围决定，不是永久禁令）：项目技能管理、自定义 Agent 登记、已有技能上游绑定/重绑的专用产品入口、旧数据兼容与迁移、市场与在线搜索、ZIP/本地文件夹导入、一键翻译、代理设置、多界面语言、历史版本查看与恢复、托盘预设操作、Hermes 档案生命周期管理与 `SOUL.md`、按预设分配档案。来源记录仍服务既有技能的上游检查/更新；当前无重绑入口不扩大为对库文件直接维护的禁令，也不承诺手改来源后存在专门的自动重绑流程。
- 留待实现规划的事项（不阻塞规格验收）：`.manager` 具体文件格式与更新粒度、来源记录格式、覆盖层维度组合与合成顺序、中文注释注入位置与格式、译文待更新提示形式、共享部署通用性判断实现、CLI 命令语法与输出格式、工具资料文件格式与 Agent 回写接口、工具启动/激活方式、检测条件与目录判定细节。
- 正式产品的视觉与交互以[设计层](../../design/README.md)为工作入口，以当前[可操作原型](../001-skill-management-prototype/ui-prototype/index.html)、[页面与效果图索引](../001-skill-management-prototype/ui-prototype/README.md)、[DESIGN.md](../../design/DESIGN.md)、[视觉说明](../001-skill-management-prototype/visual-reference.md)及[交互细节](../001-skill-management-prototype/ui-interaction-audit.md)为验收基线。最终效果须与对应原型页面**所有可见细节一致**，覆盖布局、层级、配色、图标、间距与信息密度、文案位置、操作位置及悬停/选择/弹窗等交互；不能只保留配色而重新设计界面，也不能在实现时先改 React 再补原型。正式业务行为以本规格为准；原型演示与正式规则不一致时按正式规则调整原型并记录差异。原型没有覆盖的新状态沿用相同视觉体系，先在原型画出再实现。该约束由用户在实施交接前明确，并在 2026-11-08 升级为设计层闭环；不继承原型模拟数据或存储实现。
- 原型（`specs/001`）中的模拟数据、浏览器存储与演示 Agent 回报不代表本产品实现方式，验收以真实 SkillManagerVault、本机 Agent 目录与真实上游仓库为准。
