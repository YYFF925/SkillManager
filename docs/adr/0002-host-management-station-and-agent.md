# 本机 Host、统一管理站与内置管理 Agent

本项目要从「本机桌面 + CLI」演进为「每台电脑上的本机管理服务 + 多种入口」。桌面 GUI、远程网页和内置管理 Agent 都操作同一套本机服务，不另建第二套技能库，也不把业务规则搬出 `skill-manager-core`。

本裁决依据 2026-11-11 产品讨论。行为规格、界面原型与实现计划在后续功能目录中展开；库内容与本机状态的边界仍以 [ADR 0001](0001-library-and-local-state.md) 为准。

## 分层

| 层 | 职责 |
|---|---|
| 入口 | 本机 Tauri 桌面；统一管理站上的网页；一次性 CLI；内置管理 Agent 的对话 |
| Host | 本机统一操作入口：命令分发、进程内任务协调、事件、会话、鉴权对接、破坏性确认、内置管理 Agent 的 Bridge |
| Core | 既有业务规则与数据：Vault、SQLite、Git、部署、Hermes、同步 |

Host 不承载第二套业务规则。一次性 CLI 在没有 Host 时仍可直连 Core，但必须与 Host 共用跨进程写入保护（轻量文件锁即可）；Host 在跑时，CLI 优先连上 Host，避免 GUI、脚本与 Agent 同时改同一份库或状态而无协调。

不引入持久化任务队列产品。长任务（导入进度、取消、调度）维持与当前 `AppState` 同量级的进程内协调。

同一 `state-dir` 只允许一个 Host 实例（桌面与 `serve` 不得各起一套监听、调度和 SQLite）。

技术栈仍为宪章基线：Tauri 2、React、Rust Core、clap CLI、SQLite。管理站与 Host 的 HTTP 为基线内的入口扩展，不更换桌面框架。远程 API 优先与现有 Tauri `invoke` 同名的 POST；Host 向界面推送第一版用 SSE。

## 统一管理站

远程需求是**一个入口切换设备，一次只管当前那一台的完整 SkillManager 界面**，不是在同一屏里总览或批量指挥所有设备。

管理站（名称不限定实现形态：同一软件的一个角色、容器镜像或其它常驻进程均可）：

- 提供公网（或用户指定的）HTTPS 入口与**唯一**用户登录。
- 各机 Host 用设备密钥主动连出对接（类 FRP），不必对每台开放公网端口或登录页。
- 登录后切换设备，把界面与操作转到当前 Host。
- **不持有 Vault**，不代替各机的部署、Hermes 目录或内置管理 Agent 进程。

本项目为个人自用：**一个管理员账号**。登录方式为账号密码 + TOTP；登录后保持登录，保持时长可配置。绑定 TOTP 时提供二维码、密钥及一次性恢复码。

本机桌面**只管理本机**，不通过管理站切换其它设备。外出或云电脑等远程场景打开管理站。没有管理站时，本机桌面与 CLI 仍可独立使用。

设备身份（`deviceId`）从协议层预留，表示「当前连上的那一台」；第一版不建设跨机总览或中央技能库。不提供专用冲突合并界面（现有 FR-039 的三选一形态不改）。有内置管理 Agent 时，Host 把已知冲突/暂停事实自动交给当前对话，由用户当场裁决；不要求用户截图或复制现场给外部 Agent。无对话能力时仍用 002 提示。

管理站跑在已有 HTTPS 反代后面（证书不由第一版管理站自己申请）。Host 出站对接在产品上只表现为「连接到管理站」（地址 + 一次性对接码）；可改名、可解除。离线设备能看见、不能操作。同一 Host 允许多个网页会话；破坏性确认绑当前会话。管理站首次启动创建那一个管理员并绑定 TOTP；丢失恢复码时在管理站那台机器上用本地命令重置。

## 内置管理 Agent

内置管理 Agent 是 SkillManager 产品内的一等能力：在桌面或经管理站打开的网页里对话，完成与 GUI 同类的库管理、部署、上游、注释等操作。它不是把任务复制到软件外的 Cursor/Codex；也不是 GLOSSARY 里「内置 Agent 名单」那种部署目标。

它跑在**被管理那台机器的 Host 上**（成熟 Agent CLI 作为 Host 拉起的子进程，经 ACP 接入）。浏览器不跑模型。管理站切到哪台，就用哪台 Host 上的 Agent 改那台的库与本机目录。

不把 Agent 运行时编进 `skill-manager-core`。不把第三方 Agent CLI 打进 Skill Manager 安装包，也不要求用户必须先自行装好：先检测本机已装，没有则在软件内安装/启用（类似 ACP Registry）。云电脑由该机 Host 在首次使用时装到自己的目录。认证与模型仍归那家 CLI，SkillManager 不代管、不把密钥存进管理站。具体默认安装哪一家，等 ACP 能力探测后再锁；锁定后由安装 Skill 指导那台机器上的管理 Agent 完成该 CLI 登录。ACP 是优先接入层。工具接到 Host 的第一路径是现有 JSON CLI（经 Host 转发）；第一版不另做 MCP。快照不够时 Agent 用这些工具主动查询。Host 向该 CLI 注入与配套维护 Skill、安装 Skill 分开的内置管理说明（应用资产，不入库到用户库）。不得绕过 Host 直打 Core。

内置管理 Agent **只响应用户在对话中发起的任务**。不做人无人指令时的「主动维护」（定期巡检、自动采用上游、自动入库、自动安装升级、无人值守 push 等）。既有调度器（上游检查、库拉取、工具版本检查、刷新已有部署）继续由 Host 后台跑，与 Agent 无关。以后若要主动维护，另开专题，不在本决定范围内实现。

内置管理 Agent 相对外部 Agent 最重要的差别不是「不许用外面的模型」，而是**软件自动给足上下文**，分两层：全局（库里有哪些技能、分类标签、待更新、译文待更新、部署情况、失败与暂停、以及预设/Hermes/工具等摘要）与当前界面（打开了哪个对象及其详情、上游等）。举例不是穷尽。客户端只报页面与选中引用，详情由 Host 从 core 补齐。快照是摘要、计数与引用，不含整库正文。用户不必截图、复制错误或点名对象。界面层按 GUI 会话隔离；任务在发出时钉死当时两层快照，切页不改变正在执行的任务。用户可取消进行中的任务。对话存在该机 Host 的本机状态目录，不进 Vault。快照与工具结果进入当前选用 CLI 所连接的模型。

## 无窗口 Host 与新机器接入

交付三个角色、同一套软件：本机桌面（内嵌 Host）、无窗口 Host、管理站。不为云电脑另做精简安装包。

无窗口 Host 按本机服务运行：随系统开机启动，关机即停。第一版不做唤醒休眠电脑或额外保活。软件必须提供可复制的启动命令，用户或那台机器上的 Agent 都能把已关闭的 Host 拉起来。

新机器上的 Vault 仍是 **git clone**，不做图形克隆向导。软件提供一键命令（clone 已有远端并接入本机 Host）。云电脑上通常已有编码 Agent：另提供**安装 Skill**（与配套维护 Skill 分开），指导该 Agent clone Vault、配置并启动 Host、对接管理站；CLI 选型锁定后再补「配置该 CLI 登录」等步骤。

远程网页覆盖当前桌面的技能管理能力；托盘、关窗收起、桌面应用更新在网页上不出现。路径类配置填 Host 所在机器上的路径，不用浏览器本机文件选择器。

## 确认

Host 须能验证破坏性操作：生成带 id 的操作计划（动作、参数、对象预览），由当前客户端确认该 id 后再执行。不得采信 Agent 口头「用户已同意」。

须走确认计划的仅两类：

- 删除技能（含因此清理受管部署）；
- 覆盖（包括覆盖部署副本、`--overwrite-local` 一类丢弃副本独有改动）。

改注释、分类、标签、普通部署、以及远端 push **不**逐步确认。push 次数多，逐步确认体验差；GUI 既有的自动上传一次性授权（FR-038）不改成每个 push 弹窗。远程与内置管理 Agent 的 push 同样不增加逐步确认。

## 后果

- 后续功能规格应分「本机 Host 能力」与「管理站入口」，不要为远程再实现一套 core。
- 远程网页复用现有 React 页面，对着当前设备的 Host 说话；本机路径类操作（打开 Vault、Agent 技能目录等）选的是 Host 所在机器上的路径。
- 公网暴露面是管理站，不是每台 SkillManager 的登录页。
- 外部脚本在无 Host 时仍可能改库，故跨进程锁是 Host 之外仍要有的底线。
- 不承诺新的冲突合并产品；内置管理 Agent 交付后，冲突/暂停的已知事实必须自动进入对话上下文，远程与对话不阻塞。
- 内置管理 Agent 不做主动维护；规格与实现都按「用户在对话里发起」来写。
- 002 中「软件只管理本机、不远程管 NAS/VPS 上的 Agent」由本决定取代：不 SSH 进没有 Host 的机器；已安装 Host 的设备经管理站管理其全部 SkillManager 能力。
- 新机器接入靠 clone 命令与安装 Skill，不恢复「在应用里建库」；也不把安装 Skill 与配套维护 Skill 混成一份。
