分类不在 `.manager` 中；新库布局已确定为 `code/分类/技能` 与 `lobster/分类/技能`，最多一级分类。

## 管理资料与本机记录分别处理

旧版标签真值在 `.manager`，另有 SQLite 标签索引与 `.skills-manager` 镜像。
可保留的是“库内资料为真值、索引可重建”的关系，不需要继承三份存储。

**部署记录不是管理资料镜像。** 旧 `skill_targets` 留在本机 SQLite，未写进库内镜像
（`skill_store.rs:43-57`、`sync_metadata.rs:165-181`）。它记录本机部署目标，不能把它当成
可由远端技能内容恢复的标签索引。这也符合本项目 ADR 的本机边界。

旧版对不同资料的权威关系并不统一，例如预设曾是 DB 主、文件镜像；不能把旧标签策略
泛化成整个旧系统的统一模型。新项目共享的管理资料、预设及指令源按自己的需求存入 SkillManagerVault。

## 标签治理与分类联动

旧 `get_all_tags` 从实际标签关联中取不同值，无独立词表表
（`skill_store.rs:1379-1384`）。重命名/删除时遍历受影响技能，先改 `.manager`，再改索引
（`skills.rs:4418-4603`）。同一技能已有新旧两个标签时合并，删除标签只移除关联，不删技能。
这些行为服务本项目已确认的两库共用标签名、全库治理与批量增删。

若采用缓存，局部修改后应删除旧标签桶中的关联，再加入新关联；空桶不应继续显示
（`skills.rs:435` 的 `apply_skill_to_index`）。这是避免改名后筛选仍显示旧标签的具体经验，
不要求复制旧内存索引架构。

分类由目录派生；旧 `category_of` 区分未分类、一级分类和更深路径。
旧 `move_skill_to_category_internal`（`skills.rs:1249`）执行目录移动后更新索引，
只删除搬空的旧分类目录。旧符号链接修复不适用于本项目独立副本部署。

**入库默认分类并非同一算法**：旧 `derive_source_category`（`skills.rs:3783`）取来源子路径的
倒数第二段；它既不统计仓库技能数，也不提供仓库名默认值。只能借鉴路径段读取。
新项目多技能仓库默认按仓库名、GUI 可修改、CLI 询问名称、单技能不自动分类，不能宣称旧函数已满足。

## 读写管理资料的小实现点

- `update_metadata`（`manager_meta.rs:259-302`）读、改、写同一文件；解析失败时报错而不当空文件覆盖。
  防止“只改一个标签”却抹掉同文件中的支持声明与注释。
- `normalize_tags`（`:249-257`）由文件与索引写入共用，避免空白、排序差异造成无意义变更。
- 中文正文在旧列表中只返回 `has_zh_body`，打开详情才读取
  （`skills.rs:250-252,671-706`）。不需为每张卡片加载全文。
- JSON 与正文的单文件原子写可参考[内容合成参考](content-composition.md)；
  它防止中断留下半个资料文件，不提供多文件或 Git 事务保证。
- 若保留本机索引，文件写成功后再更新索引，避免界面接受了一项未实际落盘的修改。

这些是可评估的小实现点，不是要求引入旧仓库锁、镜像、版本迁移的整套组合。

## 部署消费边界

旧 `render_to_staging` 的基本方法是复制原始树（排除 `.manager` 与 `.git`），
再复制目标 Agent 的覆盖树，同路径覆盖层胜。部署内容哈希按最终暂存产物计算
（`skill_render.rs:53-75`），可区分“仅改阅读译文”与“覆盖层影响实际部署”。

旧版的限制不能继承：

- 仅 `source_type == "skillvault"` 才合成，其余来源不合成。
- `validate_overlay_level`（`skill_render.rs:155`）拒绝覆盖层出现 `SKILL.md`。
- 中文注释保存时直接改写库内 `SKILL.md`（`skills.rs:4261`、`installer.rs:192`）。
- 支持声明部署过滤仅对旧 vault 来源生效，没有 OS 过滤，也没有支持收窄后的警告保留语义。

新项目所有来源都按支持声明与覆盖层处理，允许整份正文替换；注释仅在部署产物中加入。
组合维度与注入顺序由后续实现设计确定。详见[部署参考](deployment-pipeline.md)。

## 上游与本地资料共存

已确认的规则是：入库继承上游管理资料；更新时上游提供同项则采用上游值，未提供则保留本地，
分类保留用户归属。此规则不随来源是否由用户自建而改变。

旧外部 Git 更新只显式搬运本地 `comment`；旧 vault 导入则整体替换 `.manager`
（`skills.rs:2918-2938`、`skill_vault.rs:1570-1579`）。两条路径不同，都不能完整满足新规则。
而且旧 Git 更新的内容哈希忽略 `.manager`，仅管理资料变动可能不进入替换分支，
见[上游参考](upstream-updates.md)第二轮复查补充。

保留“是否提供某项”的信息才有可能执行上述规则；新文件格式如何表示缺省、空值与更新粒度
尚待设计。不能直接把旧反序列化默认值当成“上游显式提供”。

## 不带入与验证限制

移除旧 v1/v2 双代读取、写时升级、中文显示名/简介、DB 标签迁移、来源相关只读门、
完整 SQLite 建表及三份镜像流程。旧十字注释限制不作为新限制；新要求是通常不超过二十字。

“译文待更新”、OS 支持声明、组合覆盖层、按项保留管理资料是现有需求所需的新实现，
旧代码无完整对应链路。字段及文件级粒度仍未定，不因此追加用户需求。
旧测试中依赖作者 `F:/workspace/个人Skill合集` 的用例有环境跳过，不能作为本次运行证据。
