# 中文注释与覆盖层合成参考

本资料只保留实现思路和案例，不固定管理层格式或覆盖顺序。
当前需求：原始内容在 SkillVault 维护；部署时加入中文注释并合成目标适配；
阅读用中文译文不自动替换部署正文。完整正文覆盖是允许的操作。

## 中文注释写入的旧实现线索

旧实现将中文注释放入 `SKILL.md` 的 frontmatter（文件头元数据）`description` 前部，
而不是只加一段正文，因为旧观察中的技能菜单消费 `description`：

```yaml
description: 图表生成｜Create diagrams
```

这是可评估的技术路线，不保证所有 Agent 的菜单都采用同一展示方式。
实施注释时可以参考旧 `set_description_prefix_in_content` 的“旧前缀→新前缀”纯文本变换思路，
但不能搬旧安装流水线：本项目是在部署产物注入，不改库内原始正文。

| 案例 | 需要观察的结果 |
|---|---|
| 第一次填写注释 | 原英文描述仍存在，新增中文解释 |
| 修改／清空注释 | 只替换属于管理器的旧前缀，不误删原描述 |
| 重复合成同一注释 | 不重复堆叠前缀 |
| description 有引号、换行或块标量 | 保持有效元数据，不把复杂值当单行截断 |
| 名称及正文 | 不因注释而改名或改写原始正文 |

旧函数只支持部分单行形态，旧录入上限也是旧产品规则，不能直接变成新限制。
读取与写入应针对同一个实际入口文件，避免修改一个文件却由 Agent 加载另一个文件。

## 覆盖层合成

可复用的简单思路：取得基础文件集合，排除管理专用内容，按已选目标叠加适配文件，
生成给目标使用的文件集合。源技能不因合成而被写入目标特有内容。
覆盖层的路径、OS／Agent 组合顺序和正式存储格式仍由本项目设计确定。

**旧校验器不能原样复制**：它拒绝 overlay 中的 `SKILL.md`，与当前允许整份正文替换的需求冲突。
旧版“仅 vault 来源才合成”的分支也不适用于统一维护模型。

适合按实际功能验证的案例：无覆盖层、添加新文件、替换同路径文件、整份 `SKILL.md` 替换、
目标差异、嵌套目录、文件／目录同名，以及部署产物不包含 `.manager`。
这些是相关案例线索，不要求为所有理论边界增加额外机制。

## 第二轮补充：Agent 指令合成

旧 `compose_instructions` 是可以单独理解的纯函数：全局指令在前、工具专属指令在后，
两侧去掉首尾空白后用一个空行连接；一侧为空就只返回另一侧，双空得到空内容。
源文件读入时的 CRLF／LF 处理可作为跨平台案例，不需要把整个旧指令服务一起搬入。

本项目已确认清空后覆盖目标，因此不能因内容为空而保留上次分发的旧文本。
实际源目录、分发目标选择及调用方式遵循本项目要求，不继续依赖旧 `central_repo`。

旧 `read_source` 会把非 NotFound 的读取失败也折叠为空内容，只写警告。
这条路径不能原样复用：源文件未读取成功后继续分发，可能把已有 AGENTS.md 清空。
应让真正的读取失败可见，不能把失败当作用户明确清空；这与“不做目标冲突检查”是不同问题。

来源：`src-tauri/src/core/agent_instructions.rs` 中的 `read_source`、`compose_instructions`、`save_sources`。

## 第二轮补充：小配置文件写入

旧 `atomic_write_bytes` 使用同目录临时文件，写入完成后替换目标，供管理资料与 Hermes 配置写入调用。
可参考它避免“写到一半中断留下截断文件”的做法；管理资料截断可能导致用户资料无法读取，
Hermes 配置截断可能直接影响工具启动，因此值得在实际写入设计中处理。

这只是单文件写入技术，不提供多文件或 Git 同步的事务保证，也不要求复制旧 sidecar 索引、
UUID 命名策略、全局锁或恢复系统。具体库与替换行为需结合当前平台验证。
来源：`src-tauri/src/core/sync_metadata.rs` 的 `atomic_write_bytes`。
